- 날짜: 2026-10-08.
- 근거: [제품 요구 추가](../01_PRODUCT_SPEC.md#배포-기반-우선-개발-2026-10-08), [별 소비·상태 변경 조사](../reviews/2026-10-08-game-state-audit.md).

## 1. 사용자 요구와 범위

현재 Mac mini + Colyseus + PocketBase + Cloudflare Pages를 유지한다. Supabase·Vercel로 이전하지 않는다. 활동 중 배포로 이동·별 획득·연결이 체감 중단되지 않아야 한다. 구버전 방이 비기를 무기한 기다리거나 정산 후 재접속시키는 방식은 수용하지 않는다.

PocketBase·Mac mini 재부팅의 무중단화는 제외한다. 실제 접속 불가 상황에는 백엔드와 독립된 안내 화면이 필요하다. 기능을 최소화한 게임으로 시스템을 검증하고 이후 확장한다. 별 소비·사용자 상태 조사를 마쳤고, 최초 요청은 기존 게임 격리·최소 게임 재제작·PocketBase/Colyseus 설정·배포 도식 정리였으며, 이후 사용자 우선순위에 따라 동기화·활동 중 worker 교체까지 로컬 구현·검증했다.

## 2. 최소 게임 범위

- 포함: 새 환경 전용 게스트 식별, 최소 닉네임과 기본 모습, 메인 로비 하나, 정원 100명, 이동·충돌·서로 보기, 별 생성·획득·주기 정산, 사용 가능 별과 정산 대기 별 구분, 실제 장애 안내.
- 보류: 플레이 중 캐릭터 변경, 상점/옷장/펫 변경, 가구 편집, 미니룸, 다른 장소, 채팅·인사. 원장·보유품·프로필은 보존한다.
- UI뿐 아니라 변경 API·실시간 메시지·장소 진입에도 기능 정책을 적용한다. 오래된 탭의 보류 요청 때문에 접속을 끊지 않는다.
- 처음에는 기존 공급 규칙으로 정산을 검증하고, 이어 100명에 맞는 공급 규칙을 별도 검증한다. 정원 확대와 별 공급 확대, 배포 전환을 한 번에 바꾸지 않는다.
- 소비 검증은 다음 단계에서 기존 상품 한 종류로 재개한다. 별만 획득하는 시험을 통과해도 구매/장착의 안전성이 검증됐다고 표현하지 않는다.

### 로컬 구현 경계

- 기본 `npm run dev:all`은 최소 게임을 실행한다. 프런트 `minimal/game/`, 공용 규칙 `minimal/shared/`, 실시간 서버 `colyseus/minimal/`, PB 훅 `pocketbase/minimal/`을 사용한다.
- 기존 원본은 이동·삭제하지 않고 기존 import 및 운영 배포 경로를 보존한다. `npm run dev:legacy`로 별도 실행한다. [보존 안내와 원본 manifest](../../legacy/README.md)를 참조한다.
- 새 DB·관리자 파일·outbox는 `.local/minimal/`, 포트는 5270/12620/18120이다. 기존 환경변수·브라우저 인증 저장소를 재사용하지 않는다.
- 현재 로비는 최대 100명, 동일 프로세스에서 두 번째 로비 생성을 금지한다. 별은 초기 5개·6초당 1개·맵 상한 12개·3분 또는 총점 64 정산이다. 공급량 확장은 아직 분리된 후속 작업이다.
- 실패 outbox 파일을 남기면서 다른 매치를 처리하고 전체 매치 재전송을 검증한다. 지갑은 개인별 원장과 확정 ID를 함께 읽는다. 없는 사용자로 구성된 매치를 임의로 부분 지급하지 않는다.
- [실행/API 안내](../../minimal/README.md), [현재와 목표 도식](../diagrams/zero-downtime.html). 검증 결과는 PROJECT_STATUS 정본에 기록한다.

## 3. 목표 구조와 반드시 지킬 계약

1. Colyseus의 연결·세션·방 식별은 유지되는 접속 계층이 소유한다. 게임 판정은 교체 가능한 worker로 분리한다. 단순 WebSocket 프록시만 추가하면 백엔드 종료 시 연결이 끊기므로 충분하지 않다.
2. 접속 계층이 입력에 순서를 부여하고 현재 worker만 결과를 확정한다. 신규 worker는 상태와 이후 입력/확정 이벤트를 받아 준비하며 외부 저장·broadcast는 수행하지 않는다.
3. 특정 입력 순서와 게임 틱을 기준으로 처리 권한을 바꾸고 이전 세대의 늦은 응답을 차단한다. 순서 재생·중복 제거는 클라이언트의 현재 이동 `seq`만으로 대체하지 않는다.
4. 상태에는 위치 외에 이동 예산·시간·`ack/fix`, 모든 점수(퇴장한 득점자 포함), 별 ID·생성 카운터·다음 생성 시각, `matchId/endsAt`, 입퇴장 중 요청이 포함된다. 난수·UUID·시각·외부 응답은 재생 가능한 값으로 취급한다.
5. DB 쓰기는 지속되는 정산 처리 계층이 소유한다. worker가 반환한 정산 명령은 결정된 ID로 중복 제거하고, 디스크 저장 뒤 통지한다. 같은 outbox 디렉터리에 여러 프로세스가 임의로 flush하지 않는다.
6. 후보 worker 준비 실패·처리 지연·상태 계약 불일치는 전환하지 않고 기존 worker를 유지한다. 전환 후 복구도 최신 상태에서 계속해야 하며 과거 snapshot으로 되돌려 보상을 없애지 않는다.
7. 기존 브라우저와 상태 스키마를 호환시킨다. 충돌 맵/이동 규칙을 동시에 바꿔 구버전 브라우저의 정상 입력이 거절되는 변경은 일반 worker 교체 범위에 넣지 않는다.
8. 접속 계층 자체 업데이트와 최초 구조 도입은 별도 전환 절차가 필요하다. 기존 TCP/WebSocket을 새 프로세스로 자동 이전한다고 가정하지 않는다. 게임 worker 배포 검증과 이 경계를 혼동하지 않는다.

S6의 운영 대상·100명·30분 승인은 이미 받았다. 다만 사용자가 선행 문제 해결을 요청했으므로 현재 시작하지 않는다. 테스트 계정을 사전 발급한 부하 검사와 공유 IP에서 신규 가입하는 입장 검사는 구분한다. 운영 정산/계정 삭제를 정리 편의로 강행하지 않는다.

## 5. 배포 수용 기준

- 정상 배포 유발 연결 종료·재접속·입력 차단·장애 안내: 0건.
- 입력 누락/중복 확정, 배포 유발 위치 되돌림, 별 중복 획득·정산 누락/중복: 0건.
- 동일 논리 로비·정원·세션 유지. 상태 인계 때문에 별/기간/사용자 위치가 초기화되지 않음.
- 50ms 틱을 기준으로 서버 인계 구간을 계측한다. 전환 자체의 추가 지연 목표는 1틱 이내로 제안하되 아직 실측·보장된 값은 아니다.
- 배포 없는 구간과 배포 구간의 snapshot 간격·입력 승인·별 획득 응답 지연 p95/p99/최댓값을 비교한다. 평균이나 연결 개수만으로 체감 무중단 통과를 선언하지 않는다.
- 실제 브라우저 최소 2개로 내 캐릭터와 타인 캐릭터를 측정하고 나머지는 합성 사용자로 보충한다. 로컬 이동 예측만으로 서버 정체를 숨기지 않았는지 확인한다.
- 후보 실패·중복 저장 명령·늦은 이전 worker 응답·반복 배포·복구 경로를 포함한다.
- 공급량은 설정과 실제 생성·획득·기간별 합계를 함께 기록한다. 100명 모두 획득하게 유도하는 시나리오와 일반 경쟁 시나리오를 구분한다.
- 첫 버전에는 구매가 없으므로 잔액 차감·전체 기능·PB 업데이트·호스트 재부팅의 무중단을 검증했다고 표현하지 않는다.

## 6. 접속 불가 안내

최소 프런트에 `/unavailable.html`과 앱 내 연결 실패 화면을 구현했다. Cloudflare Pages 배포는 후속 운영 단계다. PB 인증 실패와 게임 서버 장애를 구분하고, 지갑 조회 재시도는 실패 횟수에 따라 간격을 늘린다. 입장 실패는 대기 후 사용자가 다시 시도하며 정상 배포의 무중단 전환과 구분한다. 429는 대기 안내, 닉네임 충돌은 입력 수정, 실제 연결 불가는 상태 확인/재시도로 처리한다. 마지막 정상 정보·자격증명을 보존하고 확인하지 않은 정산의 성공을 표시하지 않는다.

백엔드가 모두 꺼져도 안내 화면이 열리는 것을 로컬/검증 환경에서 시험한다. 이는 호스트 무중단 요구가 아니라 장애 시 사용자 안내 요구다. 이 계획을 이유로 운영 PocketBase나 호스트를 중단하지 않는다.

## 7. 로컬 구현 결과 (2026-10-08)

S3/S4/S5를 main 체크아웃에서 구현·검증했다. 결과와 실패 증거·측정 한계는 [PROJECT_STATUS](../03_PROJECT_STATUS.md) 7절, 프런트 전달 사항은 [worker 계약](../handoffs/2026-10-08-worker-contract.md)을 따른다. 사용자 최신 지시가 우선하므로 S6 이전 승인과 무관하게 이번 세션에서는 운영 접근·배포를 하지 않았다. 보존 중인 기존 로컬 서버에는 최초 구조를 반영하지 않았다.

진행 갱신(2026-10-08): S1~S5 구현·로컬 검증 완료. S6 최소 서버 별도 도입과 공개 백엔드 경로 추가 완료, 공개 100명/30분 검사 통과, Pages 게시 확인 진행 중. 상단 상태 표시는 Claude 구현과 Codex 실제 두 브라우저 교체 검사를 통과했다. 실 서비스 제작·자원 정리 기준은 [인계](../handoffs/2026-10-08-minimal-service.md), 실제 완료 결과는 PROJECT_STATUS를 따른다.
