# PLAN-001 — 로컬 픽셀 타운 구현과 계약 정리

- 상태: `DONE` — 화면·맵·충돌은 사용자 거절로 [PLAN-002](PLAN-002.md)가 대체. 백엔드 계약은 유지.
- 날짜: 2026-10-02
- 관련 요구사항: FR-001–008, BR-001–011, AC-001–013
- 관련 결정: [ADR-001](../decisions/ADR-001.md)
- 담당: 메인 조율 / 프런트엔드 / 백엔드 / 검증 / 문서 병렬 담당

## 1. 목표와 범위

자체 도트 2D 타운을 React/Vite Canvas로 실제 플레이 가능하게 만들고 PB 인증·사용자별 저장과 Colyseus 방·서버 판정을 연결한다. localhost 20명 smoke까지 검사하고 공개 GitHub 소스로 전달한다. 100명 운영·원 서비스 접속·PR·merge·운영 배포는 이 계획의 완료 조건이 아니다.

## 2. 현재 상태와 전제

계획 작성 시 `game/src/main.jsx`, `game/src/world.js`, `colyseus/*.js`, `pocketbase/pb_hooks/matches.pb.js`, 실행·seed·통합 스크립트가 이미 존재하며 병렬 변경 중이다. 이 계획은 개발 시작 전 작성된 계획처럼 소급하지 않는다. 실제 작업 상태·검증은 PROJECT_STATUS가 정본이다.

회원가입 제외(개발 계정·기존 로그인만 제공)는 확정했다. 프런트엔드 `VITE_GAME_URL`, 상위3 scoreboard·동점 순위, 채팅 overlay 계약을 구현했다. 신규 필수 규칙은 방별 초기 별 5개·미회수 상한 12개·1500ms마다 상한 미만에서 1개 생성·회수 후 후속 주기 재생성·기본 30초 종료(별 0개 조기 종료 없음)다. 점수 검증 상한도 64로 변경한다. 별·시간·위치·점수는 서버가 결정하며 사용자별 authRefresh 인스턴스, PB 트랜잭션, `(match_id,user)` unique, 디스크 outbox와 재시작 복구를 유지한다.

## 3. 실행 단계

추가 사용자 요청: 같은 부모 아래 game/pocketbase/colyseus/docs 형제 디렉터리로 구성하고 기존 개발 데이터를 보존한다. 루트 launcher·설정·통합 테스트·문서 경로를 함께 변경한 뒤 전체 핵심 흐름을 재검증한다.


1. 문서: 게임기획·PRD를 한 정본에 작성하고 FR/BR/AC를 연결한다. 기술 계약과 미확정을 실제 코드에서 추출한다. 기존 analysis·상태·루트 README 담당 영역을 보존한다.
2. 구현: 프런트엔드는 게임 중심 UI·모바일·채팅 overlay·scoreboard·환경변수·인증 UI, 백엔드는 인증·방·충돌·게임·저장 계약을 확정한다. 독립 변경은 병렬 수행한다.
3. 검증: clean build, 두 계정 기능, 부정 입력·개인정보 접근, 종료·보상, 재전달·트랜잭션 rollback·저장 장애·재시작, 20명 smoke, 브라우저 UI와 미회수 별 cap/무회수 누적 방지/회수 후 재생성을 확인한다.
4. 수정·정리: 실패 원인을 고치고 관련 항목 재검증, 최종 소스와 TECH_SPEC 재대조, 메인 담당의 상태·README 업데이트, 단계별 한국어 커밋과 승인된 공개 저장소 push.

## 5. 검증 계획

수용 기준은 PRODUCT_SPEC 8절을 따른다. 통합 자동 검증은 AC-001/003/004/005/007/009/010/012의 서버 계약을 중심으로 하고, AC-002는 개발 계정 입력·기존 로그인·회원가입 UI 제외를 검사한다. 브라우저 모바일 모의 확인은 AC-004/006/008/011과 기본 30초를 보완한다. 실제 모바일 기기 검증으로 표현하지 않는다. AC-013은 여러 생성 주기를 기다려 상한 이상 생성이 없는지, 별 회수 후 다음 주기에 1개만 재생성되는지, 별 0개여도 진행 상태를 유지하는지, 장소 간 상한이 격리되는지 확인한다. 20명 테스트의 기간·입력률·snapshot·채팅 지연·단일 머신 한계를 기록한다. 100명 통과를 추론하지 않는다.

## 6. 위험과 미해결

- 병렬 변경으로 endpoint·환경변수·payload가 달라질 수 있다. 종료 직전에 소스를 다시 읽는다.
- PB가 동작해도 프로필 없는 신규 사용자는 방 인증을 실패할 수 있다. 회원가입은 제외하고 기존 계정의 프로필을 준비한다.
- 저장 실패 시 pending과 재시도를 보여주고 outbox 파일을 남긴다. 디스크 쓰기 실패를 성공으로 표시하지 않는다.
- analysis.md의 원본 조사관찰을 보존하고 메인 담당이 갱신한 현재 데모 트랜잭션 설명을 따른다.
- 상태·README를 다른 담당과 동시 편집하지 않는다. 결과 증거는 검증 담당 산출물에서 확인한다.

## 7. 완료 조건

요구 범위 구현, 수용 기준 확인과 필요한 검증, 발견한 문제 수정, 명세·코드 대조, 메인 담당의 최신 현황·인수인계, 승인된 단계별 commit·push가 마무리되면 메인 담당이 상태를 갱신한다. 구현·통합13개·단위6개·30초 브라우저 플레이와 조회·화면 크기 검증을 마쳤다. 기획과 게임 단계는 push했고 검증 단계로 증거와 인수인계를 게시한다.
