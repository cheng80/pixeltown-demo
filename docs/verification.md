## 9. 미실행·한계

- 실제 iPhone/Android 기기, OS 가상 키보드, 저사양 기기 FPS는 확인하지 않았다. 브라우저 모바일 에뮬레이션(DPR3, touch)만 사용했다.
- 미니룸 캡처에서 펫이 주인 몸 뒤에 완전히 가리던 문제(정면을 볼 때 펫 목표가 주인 바로 북쪽)를 고쳤다. UI 검사가 정면 방향 펫 오프셋(dx −14)을 단언한다.
- 클라이언트 예측이 없다. localhost에서는 50ms 틱 보간으로 충분했지만 인터넷 지연 환경의 조작감은 측정하지 않았다.
- 디자인 승인은 사용자 판단 대상이다. 위 스크린샷이 판단 자료다.
- 연습 모드(혼자 둘러보기)는 이동·별 생성·연습 점수만 확인했고 서버 기록은 만들지 않는다. 연습 모드에는 상점·미니룸이 없다.
- 다른 사람의 미니룸 방문은 범위 밖이다. 미니룸은 자기 브라우저에서만 걷는다.
- 브라우저 상점 검증은 개발 DB에 임시 계정(`ui-*@pixeltown.local`)과 지급 별을 남긴다.

### 원격 별 회수 실패 조사

- 증상: 원격 `star_cap_collect_and_refill`이 `walk timeout`으로 실패했다. 같은 검사가 앞선 실행에서는 통과했다.
- 재현: 원격에서 별까지 걷기를 반복하자 5개 중 2개, 5개 중 1개가 25초 안에 도달하지 못했다. 로컬에서는 5/5 도달했다. 입력→이동 지연은 원격 97–214ms, 로컬 35ms였다.
- 원인 1: 플레이어가 소품 가장자리처럼 실제로는 서 있을 수 있지만 8도트 격자 칸 중심이 막힌 곳에 서면, `findPath`가 빈 경로를 반환했다. 예: 오락실 (233.8, 371.6), 광장 (616.2, 21.8). 테스트는 직선으로 걷다 오락기에 끼었다. 실제 화면에서는 그 자리에서 클릭 이동이 반응하지 않는다. 원격에서는 지연 때문에 이런 위치에 멈출 일이 많아 원격에서만 드러났다.
- 원인 2: 위치 반올림으로 웨이포인트와 0.03도트 어긋나면 `moveActor`의 모서리 비켜가기 조건(`!sx`)이 꺼져 모서리에 멈췄다. 예: 광장 (419.97, 177.29) → (420, 196).
- 수정: 시작 칸을 직진 가능한 가장 가까운 걷는 칸으로 고르고, 문자열 당김이 시작점에서도 직진 여부를 검사한다. 비켜가기는 거의 축 방향(다른 축 성분 25% 미만)일 때도 동작한다. 클라이언트는 클릭 이동 중 0.5초 동안 움직이지 않으면 현재 위치에서 경로를 다시 찾는다.
- 확인: 단위 회귀 테스트(위 표), 원격 걷기 진단 10/10 도달(지연 82–91ms), 원격 검사 8/8.
- 연쇄 실패 정리: 같은 회차에서 상점 검사는 반복 실행으로 싼 미보유 품목이 떨어져 실패했고(서버 정상), 캐릭터 검사는 그 때문에 상대가 다른 방에 남아 실패했다. 두 검사를 각각 독립적으로 동작하게 고친 뒤 통과했다.
- 기타: 통합 테스트 셋업이 한 번 0.6초 만에 "Something went wrong."로 실패했다. 이후 통합 테스트 4회 연속 통과해 재현되지 않았고 원인은 확인하지 못했다.
