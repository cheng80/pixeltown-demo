# Claude 요청: 상단 배포 상태 표시

사용자 요청(2026-10-08): 미니멀 픽셀타운에서 배포 진행 상태를 상단에 표시해 눈으로 확인한다. Codex는 화면 파일을 수정하지 않는다. Claude 화면 구현과 모의 검사는 끝났다. Codex 실제 로컬 두 브라우저 6회 교체도 통과했다. 공개 화면 확인은 운영 게시 후 진행한다.

## 상태 계약

같은 방에서 서버가 `deployment` 메시지를 보낸다. 매 `snapshot.deployment`와 `/health.worker.deployment`에도 최신 상태가 들어간다.

```js
{ phase: 'preparing' | 'catching-up' | 'applied' | 'cancelled' | 'idle',
  eventSeq: 3, updatedAt: 1791430000000,
  revision: 'SHA-256' /* 초기 준비 시 null 가능 */, generation: 2 }
```

`eventSeq`는 해당 방의 배포 상태 순서다. 방을 바꾸면 초기화하며 늦은 값은 무시한다. `seq/fix`는 플레이어 이동 계약 그대로다. 배포 번호와 이동 번호를 섞지 않는다. 메시지는 게임 입력·상태 변경 권한이 없다. 초기 입장은 snapshot의 현재 상태와 버전으로 표시한다. 상태가 없는 이전 서버에도 게임은 정상 동작해야 한다.

## 화면 요청

- 광장 화면 상단의 작은 영역에 현재 버전(앞 8자)·교체 회차를 표시한다.
- `idle`: 현재 버전, `preparing`: “새 버전 준비 중”, `catching-up`: “상태 확인 중”, `applied`: “적용 완료”, `cancelled`: “이번 배포 취소 · 현재 버전 유지”.
- 실제 교체는 수십 ms라 표시가 빠르게 끝날 수 있다. 수신한 단계를 순서대로 잠깐 보여 줘도 되지만 “표시 중인 과정”과 “현재 적용 버전”을 구분한다. 화면 표시를 위해 서버 전환을 늦추지 않는다.
- 이동·클릭·방향 패드·snapshot 처리를 계속한다. overlay, 자동 재접속, 입력 차단을 추가하지 않는다. 실제 연결 장애의 기존 안내는 유지한다.
- 준비/추격 중의 `revision`은 아직 활성 버전이다. 새 버전은 서버 `applied`를 받는 즉시 현재 버전으로 표시한다. 단계 라벨의 짧은 재생과 버전 갱신을 분리한다. 취소를 연결 장애로 표시하지 않는다.
- 표시가 게임 상태를 가리지 않도록 데스크톱/390px에서 확인한다. 접근성 안내는 상태가 바뀔 때만 갱신한다.

## 확인과 인계

같은 방에서 실제 worker 교체로 단계·버전 변경을 확인한다. `onDrop/onLeave/onError`, 장애 cover, 이동 입력 중단, 예상 밖 fix는 모두 0이어야 한다. 기존 서버에는 이 표시 계약이 아직 로드되지 않았으므로 문서만으로 운영 구현 완료라고 보고하지 않는다. 화면 완료 결과·검증·변경 파일은 `minimal/game/FRONTEND_HANDOFF_RESULT.md`에 추가한다. commit/push·서버 종료·세션 종료는 Codex 담당 범위에 둔다.
