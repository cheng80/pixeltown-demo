# 프런트 재제작 핵심 인계 — Claude Opus 5.5

## 목표

사용자는 현재 최소 게임 화면의 완성도를 거절했다. 프런트를 다시 제작한다. 기능은 작게 유지하면서 **픽셀 아트 게임으로서의 시각적 완성도와 조작감**을 확보한다. 현재 녹색 웹 카드·빈 잔디·단순 사각 캐릭터 구성을 다듬는 수준에서 끝내지 않는다. 프런트의 구체적인 아트 디렉션·구성·제작은 Claude가 책임지고 판단한다.

## 제작 기준

- 원래 목표는 싸이월드 미니홈피 감성의 아기자기한 도트 마을이다. `docs/assets/lobby-two-users-chat.png`, `docs/01_PRODUCT_SPEC.md` 1.1절, 보존된 `game/src/render.js`·`sprites.js`·`style.css`를 시각 참고로 확인한다. 기존 전체 UI를 그대로 복원하거나 기능을 다시 늘리는 요청은 아니다.
- 실제 플레이 월드가 주인공이어야 한다. 일관된 도트 크기·팔레트·타일 연결, 명확한 지형과 동선, 입체감 있는 소품·그림자·깊이 정렬, 알아보기 쉬운 2등신 캐릭터와 자연스러운 걷기 표현을 갖춘다. 거대한 지갑 카드나 랜딩 페이지가 게임을 밀어내지 않게 한다.
- 한 화면의 닉네임 입력, 플레이 중 작은 HUD, 별 획득/저장 피드백, 연결 실패 안내까지 같은 시각 언어를 사용한다. 글자 가독성·버튼 상태·터치 영역·모바일 카메라를 실제 화면에서 다듬는다. 개발 구조/테스트/worker 설명은 제품 UI에 넣지 않는다.
- 본인이 만든 그림·코드 또는 프로젝트에 사용 권한이 있는 자산을 사용한다. 새 외부 자산은 출처·사용 조건을 기록한다. 외부 원본 게임의 이미지나 코드를 가져오지 않는다.

## 기능과 소유권

- 대상 체크아웃: `/Users/cheng80/Desktop/Current_works/pixeltown-demo`의 현재 미커밋 최소 게임. 새 checkout의 HEAD에는 이 작업이 없으므로 현재 디렉터리에서 진행한다.
- **Claude 담당:** `minimal/game/`의 화면·스타일·렌더링·시각 자산·프런트 검증, 이 폴더 안의 완료 보고서. 프런트 구현을 끝내고 실행·검증한다.
- **Codex 담당:** PocketBase·Colyseus·게임 규칙·통신 계약·무중단 배포. `colyseus/`, `pocketbase/`, `scripts/`, `minimal/shared/`, 루트 설정/의존성/문서는 수정하지 않는다. `minimal/game/src/api.js`, `state.js`도 보존한다.
- `main.jsx`와 `WorldCanvas.jsx`는 화면을 재구성할 수 있지만 기존 인증·통신·seq/fix·이동 예측·충돌·서버 보정·정산 상태 처리는 보존한다. 필요한 계약/맵 변경은 `minimal/game/FRONTEND_HANDOFF_RESULT.md`에 이유와 함께 `NEEDS-DECISION`으로 남긴다.
- 포함: 닉네임, 단일 메인 로비, 최대 100명, 이동·충돌·서로 보기, 별 획득, 저장된 별/정산 대기 구분, 접속 불가 안내. 상점·꾸미기·채팅·다른 장소·미니룸은 추가하지 않는다.
- 서버 맵 `minimal/shared/world.js`가 충돌 정본이다. 장식 때문에 실제로 걸을 수 있는 곳이 벽처럼 보이거나 그 반대가 되지 않게 한다. 월드 크기·속도·별 수·정산 시간·잔액을 화면 취향에 맞춰 바꾸지 않는다.
- 연결 실패/지갑 조회 실패를 숨기거나 정산 전 별을 저장 완료로 표시하지 않는다. `/unavailable.html`은 독립 정적 페이지로 유지한다.

## 실행·완료 기준

- 실행/API 정본: `minimal/README.md`. 현재 로컬 프런트 `http://127.0.0.1:5270`, PB `18120`, Colyseus `12620`. 이미 실행 중이면 그대로 사용한다. 운영 서버에는 접근하지 않는다.
- `npm run build`, `npm run test:minimal:unit` 및 변경한 UI에 맞춘 프런트 검증을 통과시킨다. `npm run test:minimal:ui`는 모의 백엔드 검사임을 구분한다. 기존 기능 단언을 지워 통과시키지 않는다.
- 실제 로컬 서버와 두 브라우저로 입장·자기/타인 이동·별 획득·저장 표시를 확인한다. 데스크톱과 390px 모바일 스크린샷을 직접 보고 여백·화면 밀도·픽셀 정렬·겹침·가로 넘침을 고친다. 빌드 성공만으로 완료하지 않는다.
- 완료 보고서에는 핵심 변경, 바꾼 파일, 실행한 검사, 화면 캡처 위치, 남은 계약 요청만 간결히 적는다. 계정·관리자 비밀정보는 기록하지 않는다.
- 사용자 변경과 기존 게임/데이터를 보존한다. commit/push/배포, 브랜치·worktree 삭제, 다른 세션 종료는 하지 않는다. 완료 후 같은 세션에서 대기한다.
