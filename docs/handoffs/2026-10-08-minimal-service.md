# 미니멀 픽셀타운 인계와 향후 정리

갱신: 2026-10-08. 이 문서는 미니멀 게임의 배포 기반을 실 서비스 제작자에게 넘기기 위한 기록이다. 실 서비스 개발 완료나 출시 승인을 뜻하지 않는다. 실제 검증 결과는 [PROJECT_STATUS](../03_PROJECT_STATUS.md)와 [worker 검증](../reviews/2026-10-08-worker-swap-verification.md)에 기록한다.

## 무엇을 만들고 있는가

메인 광장 하나에서 이동하고, 다른 사람을 보고, 별을 모아 저장하는 게임이다. 여기서 게임 로직을 바꿔도 접속과 플레이가 이어지는지 확인한다. 상점·꾸미기·펫·채팅·미니룸은 기존 게임에 남겨 두었다. 최소 게임의 계정과 별은 기존 게임과 별도다.

사용자가 여는 주소는 `https://pixeltown.fastmake.net`이다. 화면이 사용하는 백엔드만 새 주소로 바뀐다. 기존 게임을 열어 둔 탭은 기존 서버에 계속 연결된다. 처음 구조를 도입할 때 기존 소켓을 새 서버로 옮기지는 않았다. 도입 이후에는 게임 worker를 교체해도 연결을 유지한다.

## 실 서비스 제작 때 가져갈 부분

| 구성 | 재사용 이유 | 먼저 확인할 것 |
|---|---|---|
| `WorkerHost`, worker runtime | 연결과 게임 계산을 분리하고 최신 상태를 확인한 뒤 교체한다 | 새 게임 상태와 이벤트가 체크포인트·hash에 모두 포함되는지 |
| 버전별 release와 고정 링크 | 배포 파일을 완성한 뒤 한 번에 선택한다 | 같은 상태·맵·입력 규칙을 사용할 수 있는지 |
| 단일 outbox·멱등 정산 | 후보 worker가 중복 지급하지 못한다 | 실 서비스 보상 규칙과 DB 제한 |
| `move`의 `seq/fix` | 예측 이동과 서버 보정이 교체 뒤에도 이어진다 | 새 입력 방식, 속도, 충돌 판정 |
| 장애 화면·독립 안내 | 실제 연결 장애 때 입력을 멈추고 안내한다 | 실 서비스 복구·재접속 정책 |

게임 worker 교체의 무중단과 접속 서버 자체의 무중단은 다르다. 현재는 접속 프로세스가 꺼지거나 Mac mini가 재부팅되면 연결이 끊긴다. 실 서비스에서 이 범위까지 유지하려면 별도 구조와 검증이 필요하다.

PB 단독 배포 중 연결 유지는 [PB 배포 인계](2026-10-08-pb-deployment.md)를 따른다. PB·게임 전용 실행기와 launchd 서비스를 운영에 적용했다. 공개 경로에서 SDK 1개와 실제 브라우저 1개가 이동하는 동안 PB hooks 교체·원본 복구를 확인했다. 게임 PID와 room/session은 그대로였고 끊김·재접속 안내는 0건이었다. PB 중단 중 새 입장과 지갑 조회는 실패할 수 있다. 백업 위치와 자세한 결과는 PROJECT_STATUS 7절에 있다.

## 실 서비스에서 추가로 할 일

- 전체 게임 기능을 하나씩 붙이고, 해당 상태의 인계·정산·중복 처리까지 검증한다.
- 맵·속도·메시지·체크포인트 변경에 대한 버전 이행 방식을 정한다. 현재 교체는 같은 계약을 지키는 로직에 한정한다.
- 계정·원장 이전 여부를 별도로 결정한다. 최소 게임 DB를 기존 DB에 덮어쓰지 않는다.
- 다중 방·정원 초과·인터넷 지연·실제 기기·오랜 실행을 검증한다. 합성 사용자 100명은 실제 브라우저 100명과 다르다.
- 실 서비스 운영자 계정, 백업 복구, 모니터링, 부정 입력·가입 제한을 정한다.

## 운영 검사 재실행 조건

최신 상태: 사용자의 재개 지시로 2026-10-08 17:00:42 KST에 85명·3분 worker 교체를 다시 시작했다. PID 23626, 자료는 `.test-work/minimal-live-Bb63BB/`다. 30초마다 상태와 서버·PB·Tunnel 진단을 기록하며 중지 지시까지 계속한다. 아래 15:34 중지는 이전 실행 기록이다. 최신 실행 결과는 PROJECT_STATUS 7절과 실행 폴더의 `status.json`을 따른다.

2026-10-08 15:34:59 KST, 사용자 요청으로 85명 합성 접속과 3분 주기 worker 교체를 중지했다. 시험 접속은 모두 종료했고 원본 worker를 복원했다(generation 21). 실제 접속자와 서비스는 유지했다. 자료는 `.test-work/minimal-live-KytYyv/`에 보존한다. 새 사용자 지시 전에는 `tests/minimal-live-observe.mjs`나 다른 부하 검사로 이 실행을 재개하지 않는다.

`tests/minimal-operational.mjs`는 최소 운영 서버의 합성 사용자 100명을 사용한다. 기존 게임에 사용하지 않는다. 실행 전에 승인·로비 정원·백업 위치를 확인한다. `tests/minimal-operational-control.mjs`를 최소 app의 `.test-work/operational-control.mjs`로 복사한 뒤 `MINIMAL_OPERATIONAL=1 MINIMAL_SOAK_MS=1800000 node tests/minimal-operational.mjs`로 실행한다. 최초 준비는 DB online 백업과 전용 계정 발급을 한다. 재실행할 때는 이전 private `accounts.json`을 `MINIMAL_OPERATIONAL_ACCOUNTS`로 지정해 중복 가입을 피한다. 토큰을 명령 인수·로그·문서에 넣지 않는다.

검사 중에는 로비가 100명으로 차므로 일반 입장이 거절될 수 있다. 검사는 별도 최소 서버에서 하고 기존 게임 서버에는 부하를 보내지 않는다. 성공/실패, 준비 단계 재시도, 실제 활동 시간, 교체 결과, 연결·보정·원장 대조를 모두 보고서에 남긴다. 두 실제 브라우저 검사는 합성 사용자 검사와 구분해 기록한다. 검사 완료 뒤에도 계정·자료는 보존하며 별도 정리 지시를 따른다.

배포 중 복구 주의: 고정 링크는 다음 후보를 가리킬 수 있다. 활성 worker 복구는 링크를 다시 읽지 않고 시작 때 확인한 검증 버전의 실제 파일 경로를 사용한다. 복구 상태는 마지막 확정 상태이며 과거 배포 체크포인트로 되돌리지 않는다. 이 구분을 실 서비스에서도 유지한다.


## 현재 게시 상태와 인계 시 남은 일

미니멀 구현은 `68d4ca8`으로 main에 게시했다. Cloudflare Pages의 production 소스와 공개 game bundle을 확인했다. 화면 상단에서 현재 버전/회차와 배포 단계를 볼 수 있다. 화면을 새로 열면 새 미니멀 서버에 연결하며, 이미 열려 있는 기존 게임 탭의 소켓은 그대로 둔다.

로컬·공개 100명/30분 합성 검사와 공개 100명 정원에서 실제 브라우저 두 개의 6회 교체 검사를 통과했다. 100개 실제 브라우저·실제 휴대전화의 장시간 검사는 하지 않았다. 인터넷 경로의 지연은 남아 있다. 실 서비스에서는 기기와 지역을 나눠 확인한다. 최종 수치는 PROJECT_STATUS와 worker 검증 보고서를 따른다.

지금은 이 미니멀 기반에서 worker 로직 교체를 반복할 수 있다. 전체 기능 제작, 호환되지 않는 상태 변경, 접속 서버 자체의 장애 복구, 시험 계정/예전 자원 정리는 다음 별도 작업이다. 보존 중인 로컬 서버와 개발 세션은 종료하지 않는다.

## 화면 교체 도입 뒤 추가 인계 (2026-10-08)

월드 렌더러·도트 그림·CSS·글꼴·이미지를 버전별로 나누고 플레이 중 교체하는 기능을 운영에 반영했다. [설명 그림](../diagrams/frontend-live-update.html)과 [파일·배포 계약](2026-10-08-frontend-live-update.md)을 따른다. React 화면 구성·인증·입력/충돌 규칙은 자동 교체 범위가 아니다. 사용자 승인을 받아 이번 통합 변경은 Codex가 직접 했다.

현재 운영은 미커밋 코드의 직접 Pages 배포다. 다음 승인된 commit/push에 소스·빌드·게시 스크립트를 같이 포함해야 한다. 이전 Git 자동 빌드가 다시 게시되면 기능이 사라질 수 있다. 최종 화면 버전은 `2ca05cdd`다.

이전 화면 파일은 `.local/minimal/frontend-releases/`와 Pages의 `/visual/releases/`에 보존한다. `.test-work/frontend-history-from-public/`은 새 CI 환경의 이전 버전 복원 검사 자료다. 실 서비스 이전 때 CDN 위치·보관 기간·삭제 조건·여러 CI의 게시 경쟁 제한·장시간 ES module 메모리를 정한다. 현재 검사 자료·release·백업·계정은 자동 삭제하지 않는다.

3분 자동 worker 배포는 사용자 요청으로 중지했다. 배포만 중지하려던 Codex의 검사 제어 오류로 기존 합성 85명이 일시 종료됐으며, 배포를 끈 새 실행으로 같은 계정 85명을 복구했다. 실제 사용자 연결과 서버는 유지했다. 복구 PID 17065의 `.test-work/minimal-live-2IhLNh/`는 사용자 요청으로 18:14:16 KST에 정상 종료했다(410,224 입력·미확인 0·끊김 0·배포 0회). 18:15:25 KST에는 운영 최소 게임 서비스도 종료했다. PB·Tunnel·기존 게임과 로컬 개발 서버는 유지했다. 이전 `.test-work/minimal-live-Bb63BB/`의 22회 교체·개별 1006 7건·검사 제어 실패를 별개로 보존했다. 최신 상태와 원인 분석의 남은 일은 PROJECT_STATUS 7절을 따른다.
