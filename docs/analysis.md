# 원본 분석과 구현 범위

조사일: 2026-10-02 (한국 시간). 대상: https://pixel-metaverse.vercel.app/

## 조사 방법과 한계

원본 HTML/CSS/공개 JavaScript를 한 번 내려받아 읽고, 실제 사이트의 캐릭터 설정 화면을 관찰했다. 게임 입장이 공개 MQTT에 상태를 게시하고 기존 메시지를 구독하기 때문에 원 서버에 입장하지 않았다. 원본 HTML의 로컬 임시 사본에서 MQTT를 완전한 무통신 stub으로 대체하여 게임 화면·메뉴를 관찰했다. 이 사본은 분석용 `work/`에만 있고 데모·배포 산출물에 포함하지 않는다. MQTT endpoint 문자열은 확인했지만 브로커의 가용성이나 실제 타 사용자 동기화는 검증하지 않았다. 브로커 메시지 수집·재전송 및 원 서비스 부하 테스트는 수행하지 않았다.

## 네트워크 및 신뢰 경계

공개 코드에서 `mqtt.connect('wss://broker.hivemq.com:8884/mqtt')`를 확인했다. 방별 MQTT topic을 구독·게시하고, 개인 공원과 보드 등의 상태는 retained topic을 사용한다. 닉네임과 위치의 권한 있는 중앙 검증, 게임 점수의 서버 판정은 조사한 클라이언트에서 확인되지 않았다. 이는 공개 클라이언트에 대한 관찰이며 서버 전체 보안 감사 결과는 아니다.

자체 데모는 PocketBase `authRefresh()`로 로그인 토큰을 검증하고 Colyseus가 확정한 사용자 ID만 사용한다. 클라이언트는 위치·결과를 DB에 직접 쓰지 않고 이동 입력과 별 수집 요청만 보낸다. 서버가 결과를 작성하며 사용자/match_id의 유일성·PocketBase 트랜잭션·영구 outbox 재시도를 이용해 중복 결과·보상을 막는다. 경기 결과와 보상 원장을 함께 저장하며 동일 match 재전송의 점수가 다르면 거부한다.

## 규모와 확장

초기 목표는 20명이다. 단일 머신 localhost 테스트는 인터넷 성능을 뜻하지 않는다. 100명은 별도 확장 검토 대상: snapshot 전체 전송 대신 schema delta/관심 영역 전송, 방 분할, 네트워크 왕복·모바일 렌더링·CPU 측정 후 결정한다. 초기에는 PB·Colyseus 각 단일 개발 프로세스와 Vite를 사용하며, URL 환경변수와 독립 서버 경계로 호스팅 교체를 지원한다.

참고 문서: https://docs.colyseus.io/room/lifecycle , https://docs.colyseus.io/auth/room , https://pocketbase.io/docs/api-records/ . 인증 훅은 최신 문서의 예제를 맹신하지 않고 설치된 패키지의 규약으로 구현·테스트한다.

분리된 원본 로컬 사본을 1280×720에서 측정하면 document scrollHeight=853, scrollWidth=1280이었다. 브로커 통신을 제거한 상태의 화면 레이아웃 관찰값이다. 실제 공개 서비스의 타 사용자나 라이브 미니게임은 관찰하지 않았다.
