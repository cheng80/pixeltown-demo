# 개발·문서 작업 흐름

> 팀이 프로젝트를 진행하는 공통 운영 규칙이다. AI의 읽기·갱신 경로는 `AGENTS.md`에 둔다.

## 1. 정본
- 제품 동작/범위 → `01_PRODUCT_SPEC.md`
- 기술 구조/데이터/API → `02_TECH_SPEC.md`
- 현재 진행/작업/인수인계 → `03_PROJECT_STATUS.md`
- 작업 방식 → 이 문서
- AI 진입 경로 → `AGENTS.md`
- 중요한 기술 결정의 이유 → `decisions/ADR-xxx.md`

## 2. 기획 흐름
1. 제품 명세에서 목표, 제외 범위, 사용자 흐름을 정한다.
2. 기능에 `FR-xxx`, 규칙에 `BR-xxx` ID를 부여한다.
3. 완료 조건을 작성한다.
4. 기술 명세에서 필요한 아키텍처·데이터·API를 정의한다.
5. 프로젝트 현황에 로드맵과 첫 작업을 만든다.
6. 구현에 영향을 주는 모순/누락이 없는지 확인하고 개발을 시작한다.

## 3. 작업 시작
작업자는 최소한 다음 순서로 확인한다.

`PROJECT_STATUS → 활성 PLAN(있으면) → 관련 PRODUCT_SPEC → 관련 TECH_SPEC → 관련 코드`

- 현재 작업과 범위를 확인한다.
- 기존 구현/패턴을 먼저 찾는다.
- 요구하지 않은 기능과 리팩터링을 임의로 추가하지 않는다.

## 4. 구현 중
- 명세와 코드가 충돌하면 조용히 한쪽을 선택하지 말고 충돌을 확인한다.
- 새로운 dependency/architecture 도입 전 기존 방법으로 해결 가능한지 확인한다.
- 범위 밖 문제는 현재 작업에 끼워 넣지 말고 나중 작업/알려진 문제 후보로 남긴다.
- 제품 요구 변경은 제품 명세를, 계약/구조 변경은 기술 명세를 함께 갱신한다.
- 중요한 기술 결정은 필요할 때만 ADR을 작성한다.

## 5. 작업 종료
다음 순서로 마무리한다.

`구현 → 테스트 → 완료 조건 → 작업 완료 → 현황/다음 작업 → 인수인계`

종료 체크:
- [ ] 요구 범위 구현
- [ ] 완료 조건 확인
- [ ] 필요한 테스트 실행
- [ ] 기준 문서와 코드가 일치
- [ ] 프로젝트 현황 최신화
- [ ] 다음 작업자가 바로 이어갈 수 있게 인수인계 최신화

## 6. 변경 규칙
### 제품 요구 변경
`제품 명세 → 영향받는 기술 명세 → 작업 → 코드 → 검증`

### 기술/데이터/API 변경
`영향 확인 → ADR(중요할 때) → 기술 명세 → 작업 → 코드 → 검증`

### 진행 상태 변경
제품/기술 명세에 진행률을 쓰지 않는다. `03_PROJECT_STATUS.md`만 갱신한다.

## 7. 인수인계 규칙
인수인계에는 설명보다 **이어서 실행할 수 있는 정보**를 우선한다.

반드시 남길 것:
- 현재 작업
- 완료 내용
- 주요 변경 파일
- 미완료/문제
- 실패했던 접근(재시도 방지에 가치가 있을 때)
- 변경하면 안 되는 계약·제약
- 다음 액션
- 테스트/검증 상태

## 8. 새 문서를 만들지 판단하는 기준
다음 중 명확한 이유가 있을 때만 분리한다.
- 독립적인 정본이 필요하다.
- 별도 담당자가 지속적으로 관리한다.
- 기존 문서가 지나치게 커져 탐색이 어렵다.
- 독립적인 변경 이력이 중요하다.

그 외에는 기존 4개 문서의 섹션으로 유지한다.

## 로드맵 → 계획 → 작업
- 로드맵과 작업은 `03_PROJECT_STATUS.md`에서 관리한다.
- 복잡한 작업에만 `plans/PLAN-xxx.md`를 별도로 만든다.
- 계획이 필요한 대표 사례: DB/API 변경, 여러 계층 수정, 큰 리팩터링, 마이그레이션, 복잡한 신규 기능·버그.
- 단순 수정은 계획 없이 바로 작업으로 진행한다.
- 계획에서 장기적으로 남길 중요한 결정은 ADR로 분리한다.

## 신규 작성과 이관
- 신규: 이 4개 문서만으로 작업 가능하면 완료다. 이관 게이트를 적용하지 않는다.
- 이관: 기존 정보·자산·검증 증거·미완료 상태를 제품/기술/현황/작업 흐름 문서로 재배치한다. 새 실험 없이도 새 팩만으로 과거와 현재 공백을 판단할 수 있으면 문서 이관은 완료다. 기존 docs를 접을지는 사람이 위험을 검토해 결정한다.
- 충돌은 `DOC-CODE-MISMATCH`로 남긴다.
