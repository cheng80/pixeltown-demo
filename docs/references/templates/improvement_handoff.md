# 간소형(Lite) 적용 인수인계

간소형은 파일 수를 늘리지 않는 팩이다. 표준형/확장형의 문서를 그대로 복사하지 않는다.

## 이번에 바꾼 것
- README: 사람이 관리하는 정본과 AI 진입점을 분리하고, 신규 작성과 이관을 구분.
- AGENTS: 정본 내용을 반복하지 않는 짧은 AI 읽기·갱신 라우터로 정리.
- PROJECT_STATUS: 변경된 계약 / 검증 / 재개 명령 섹션 추가. 검증은 결과·근거·날짜·리비전·유효성·공백으로 기록.
- WORKFLOW / Spec: 보존 규칙과 이관 완료 기준만 짧게 추가.

## 쓰지 않은 것
- `MIGRATION_GUIDE.md` — 간소형 유지비에 맞지 않음. 이관은 README + 프로젝트 현황의 인수인계로 충분.
- 별도 `progress/`, `02_UI_UX.md` — UI는 제품 명세의 화면 섹션.
- 빈 `assets/` 폴더.

## 신규 작성
`PRODUCT_SPEC → TECH_SPEC → WORKFLOW → PROJECT_STATUS`
완료: 이 4개 문서만으로 다음 작업자가 이어갈 수 있는가.

## 이관
기존 정보·자산·검증 증거·미완료 상태를 4개 문서로 재배치한다. 새 실험으로 공백을 채우지 않는다. 새 팩만으로 과거 결과와 현재 공백을 판단할 수 있으면 문서 이관은 완료이며, 옛 docs를 접을지는 사람이 위험을 검토해 결정한다.

## 이후 손대지 말 것
간소형에 확장형의 작업/진행 상황/인수인계 분리를 넣지 않는다. 커지면 표준형으로 올린다.
