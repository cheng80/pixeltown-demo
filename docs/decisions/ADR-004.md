# ADR-004 — 별 지갑·상점 원장과 상시 별 이벤트 정산

- 상태: 채택
- 날짜: 2026-10-02
- 관련: FR-005/011/012/013, BR-004/011/014–017, PLAN-003

## 배경

사용자가 모은 별로 옷·펫·가구를 사고, 갈아입히고, 미니룸에 가구를 배치하길 원한다. 별 모으기는 시작 버튼 없는 상시 이벤트가 되어야 한다. 기존 계약은 서버가 판정한 경기 결과만 PB에 원자 저장한다는 것이다(ADR-001).

## 결정

1. **상시 이벤트 = 주기 정산**: 방은 첫 입장 때 이벤트를 시작하고 계속 진행한다. 3분(`GAME_DURATION_MS`, 최대 5분)마다 그 기간의 점수를 기존 `commit-match` 경로로 정산하고 즉시 다음 기간을 시작한다. 맵의 별은 유지한다. 점수가 0인 사람은 결과 행을 만들지 않고, 아무도 점수가 없으면 저장하지 않는다. 한 기간 합계가 64(훅 상한)에 닿으면 즉시 정산한다. 방이 비면 정산하고 멈춘다.
2. **생성 간격·배치**: 6초(`STAR_SPAWN_INTERVAL_MS`)마다 1개, 미회수 상한 12, 시작 시 최소 5개. 후보 24곳 중 기존 별·플레이어와 가장 먼 곳을 고른다.
3. **지갑은 원장에서 계산**: 잔액 = `inventory(item=star).quantity` 합 − `purchases.price` 합. 별도 잔액 필드를 두지 않아 이중 기록 불일치가 없다.
4. **구매는 PB 훅**: `POST /api/pixeltown/shop/buy`(사용자 인증)가 트랜잭션에서 구매 행을 먼저 쓴 뒤 잔액을 다시 계산하고 음수면 롤백한다. `(user,item)` unique 인덱스로 같은 아이템 중복 구매를 막는다. 가격은 클라이언트가 아니라 카탈로그에서 읽는다.
5. **꾸미기·배치도 PB 훅**: `shop/equip`은 슬롯별 보유 아이템만, `shop/room`은 보유 가구·미니룸 바닥 범위·칸 겹침 없음·문 앞 금지만 허용해 `profiles.outfit`/`profiles.room`에 쓴다. 클라이언트는 프로필·원장에 직접 쓰지 못한다.
6. **공용 카탈로그**: `shared/catalog.json` 하나를 화면(Vite import), Colyseus·테스트(Node), PB 훅(`$os.readFile`)이 읽는다.
7. **방 표시**: Colyseus는 입장 때와 `look` 메시지 때 사용자 토큰으로 자기 프로필을 다시 읽어 snapshot의 `look`(모자·상의·펫)을 갱신한다. 클라이언트가 보낸 옷 값은 쓰지 않는다.
8. **미니룸은 개인 화면**: 서버 방 없이 자기 브라우저에서 걷는다. 다른 사람 방문은 후속 범위다.

## 대안

- 30초 라운드 유지 + 자동 재시작: 화면이 계속 리셋되어 "항시 이벤트"가 아니다. 기각.
- 정산 없이 수집마다 즉시 저장: 수집마다 PB 쓰기·outbox 파일이 생긴다. 기존 원자·멱등 경로를 재사용하는 주기 정산이 단순하다.
- 프로필에 잔액 필드: 동시성·재전송 시 원장과 어긋날 수 있다. 기각.

## 영향

- 수첩의 결과 목록은 정산 기간 단위가 된다. 0점 기간은 남지 않는다.
- 통합 테스트는 `STAR_SPAWN_INTERVAL_MS=1500`, `GAME_DURATION_MS=30000`으로 짧게 실행한다. 기본값(6초·3분)은 단위 테스트로 확인한다.
- 이미 연결된 구 버전 클라이언트가 `startGame`을 보내면 Colyseus가 미등록 메시지로 연결을 끊는다. 새로고침하면 된다.
