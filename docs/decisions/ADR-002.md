# ADR-002 — 공용 맵·충돌 모듈과 3계층 깊이 렌더링

- 상태: 채택 (재제작, 검증 결과는 PROJECT_STATUS)
- 날짜: 2026-10-02
- 관련: FR-003/009/010, BR-003/012/013, AC-014/015, PLAN-002
- 대체: 이전 `game/src/world.js`의 베이크 지형과 `OBSTACLES` 사각형 5개 (`dc2e191`)

## 배경

이전 판은 나무·건물·벤치를 지형 이미지 한 장에 미리 그리고 캐릭터만 y로 정렬했다. 캐릭터가 항상 모든 소품 위에 그려져 "뒤로 지나감"이 불가능했다. 충돌은 건물 그림 크기의 사각형 5개뿐이었다. 나무는 막지 않았고 건물은 지붕까지 막았다. 같은 사각형 배열이 프런트·서버·통합 테스트 세 곳에 복사되어 있었다. 세 장소는 색만 다른 같은 지형이었다.

## 결정

1. **공용 모듈** `shared/world.js`를 루트 형제 폴더로 둔다. 순수 JS이며 의존성이 없다. 게임(`game/src`), 서버(`colyseus/town.js`), 테스트가 같은 파일을 import한다. 담는 것: 타일맵, 소품 배치·정의, 입구·출입구, 걷기 판정, 이동 함수, 경로 찾기, 별 위치 후보.
2. **좌표계**: 월드 1단위 = 1도트. 타일 16도트, 장소마다 40×26 타일(640×416). 모든 액터와 소품의 좌표는 발밑(바닥 접점)이다.
3. **소품 정의**는 `w,h`(그림 크기), `ax,ay`(그림 안의 발밑 기준점), `foot:[x,y,w,h]`(기준점 상대 바닥 충돌 사각형), `layer`(`sort` 또는 `fg`)를 가진다. visual bounds = 기준점에서 `ax,ay`를 뺀 그림 사각형. footprint는 밑동·벽 바닥면·기둥처럼 작다.
4. **걷기 판정**: 플레이어 발 상자(10×6) 안에 막힌 타일(물·벽·울타리·생울타리·꽃밭·맵 밖) 또는 footprint가 겹치면 막힘이다.
5. **이동**: 한 틱의 이동을 2도트 이하로 쪼갠다. x·y 축을 따로 적용해 벽을 따라 미끄러진다. 한 축이 막히고 그 축 입력만 있으면 수직 방향 최대 6도트 비켜 보기를 해서 모서리 끼임을 푼다. 시작부터 막힌 위치면 가까운 걷는 칸으로 밀어낸다.
6. **3계층 렌더링**: ① ground — 바닥 타일과 납작한 장식(꽃점·러그·물·다리)을 장소당 한 번 오프스크린에 굽는다. ② sort — 소품(`layer:sort`)·아바타·별을 발밑 y 오름차순으로 매 프레임 그린다. y가 같으면 소품을 먼저 그린다. ③ fg — 아치·퍼걸러 상단처럼 항상 위에 오는 그림. 이름표·말풍선·이모트는 그 위의 UI 층에서 화면 해상도로 그린다. 그래서 나무 뒤에 숨어도 이름은 보인다.
7. **별 위치**: 시작점에서 BFS로 닿는 걷는 칸 중 어떤 sort 소품의 visual bounds에도 들지 않는 칸 중심만 후보로 쓴다.
8. **입장 위치**: 서버는 `options.entry`를 장소의 고정 입구 이름 목록에서만 받는다. 모르는 값은 기본 시작점으로 바꾼다. 출입구 매트 판정은 클라이언트가 자기 서버 위치로 하고 장소 전환을 요청한다. 권한 영향이 없는 UI 동작이다.

## 대안

- 타일 단위 충돌만 사용: 나무 밑동·가구 크기가 타일보다 작아 어색하다. 기각.
- 서버 전용 충돌 + 클라 예측 없음: 클릭 이동 경로를 클라가 계산해야 하므로 같은 정의가 필요하다. 공용 모듈 채택.
- 외부 타일맵 에디터(Tiled) 도입: 에셋 파이프라인과 의존성이 늘어난다. 맵 문자열이 짧아 코드 내 ASCII로 충분하다.

## 영향

- 서버 이동 속도·별 거리 상수가 도트 단위로 바뀐다(이동 3도트/50ms, 수집 16도트). 통합·단위 테스트의 하드코딩 장애물을 공용 모듈 경로 찾기로 교체한다.
- 서버 틱을 100ms에서 50ms로 줄여 원격 이동이 부드럽다. snapshot 빈도가 두 배가 된다. 20명 smoke로 다시 측정한다.
- 맵 문자열 변경 시 단위 테스트가 연결성·시작점·별 후보를 자동 검사한다.
