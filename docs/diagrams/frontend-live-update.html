플레이를 계속하면서
화면 코드와 리소스를 바꾸는 방법

접속과 이동을 처리하는 코드는 계속 실행합니다. 새 그림·스타일·그리기 코드를 뒤에서 준비하고, 준비가 끝나면 다음 화면 프레임부터 사용합니다. 준비에 실패하면 기존 화면으로 계속 플레이합니다.

worker와 화면 배포는 다른 일입니다

구성 요소맡은 일이번 교체와의 관계
Colyseus사용자의 WebSocket 접속과 방을 관리합니다.계속 실행합니다. 다시 시작하면 접속이 끊깁니다.
게임 worker서버에서 이동·별 획득·정산을 판정하는 실행 단위입니다. Colyseus 프로세스 안의 별도 스레드입니다.서버 반복 배포 시험의 교체 대상입니다. 자동 배포는 현재 중지했습니다. 브라우저 화면 코드를 바꾸지는 않습니다.
PocketBase(PB)게스트 인증과 저장된 별·정산 원장을 담당합니다.화면 배포 때 수정하거나 재시작하지 않습니다.
브라우저 렌더러위치와 점수 같은 게임 상태를 받아 그림으로 보여 줍니다.이번에 새로고침 없이 교체하도록 분리한 부분입니다.

어디까지 바꿀 수 있나요?

캐릭터 방향·애니메이션·도트 그림·스타일과 글꼴·이미지가 대상입니다. 이미지와 글꼴은 사용할 준비가 끝난 뒤 전환합니다. 맵의 충돌 영역, 이동 규칙, 인증·접속 처리, React 화면 구성까지 바뀌면 같은 방식으로 교체하지 않습니다. 열린 탭은 기존 버전을 유지하고 다음 입장 때 새 코드를 받습니다. 현재 미니멀 게임에는 음원이 없으며 음원 교체는 이번 검사 범위에 포함하지 않았습니다.

이 기능을 받기 전에 열린 탭은 처음 한 번 새로고침해야 합니다. 이후 호환되는 화면 버전은 자동으로 받습니다. 서버 worker 교체는 프런트 새로고침과 관계없이 연결을 유지합니다.

업데이트에 실패하면?

새 파일을 받지 못하거나 첫 그리기가 실패하면 기존 화면을 유지합니다. 적용 후 그리기 오류가 나면 직전 렌더러로 돌아갑니다. 접속과 입력 처리는 계속 실행합니다. 상단의 “화면” 표시는 현재 화면 버전이며, 기존 worker 버전·회차 표시와 구분합니다.

파일 계약·빌드·공개 절차 · 실제 검증 결과와 남은 작업 · 서버 worker 교체 도식

확인한 결과와 남은 일

운영 주소에서 화면 버전을 두 번 바꾸는 동안 같은 연결을 유지했고 이동 입력 5,175개의 서버 확인을 받았습니다. 새로고침이나 접속 장애 안내는 없었습니다. 걷기 그림이 멈춰 있던 오류도 고쳐 팔·다리 그림이 바뀌는 것을 확인했습니다. 상세 수치는 아래 진행 문서를 따릅니다.

사용자 요청으로 자동 배포와 합성 사용자 85명의 접속을 종료했고, 운영 미니멀 게임 서버도 종료했습니다. PB와 Tunnel은 유지합니다. 앞선 장시간 검사에서 개별 연결 끊김 7건이 남아 있어 원인 확인이 필요합니다. Git 코드 게시, 여러 CI의 동시 게시 제어, 오래된 리소스의 보관·삭제 기준도 후속 작업입니다.

미니멀 PixelTown의 인계 자료입니다. 새 버전 준비·전환을 구현했으며 검증 수치와 운영 반영 여부는 PROJECT_STATUS 7절을 따릅니다. 기본 도식 색상과 로컬 글꼴 대체를 사용하며 외부 파일을 요청하지 않습니다.
