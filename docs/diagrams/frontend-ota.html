화면이 늘어도
같은 방식으로 업데이트하기

로컬에서 구현했고 운영에는 아직 적용하지 않았습니다. 최종85명10+10분·20회 UI 교체·실패 주입을 포함한 로컬 검증을 마쳤습니다. 실제 검사 결과는 로컬 결과, 최신 상태는 프로젝트 현황을 따릅니다.

OTA는 새 코드와 파일을 인터넷으로 받아 적용하는 업데이트입니다. PixelTown에서는 게임을 계속 실행하는 부분은 유지하고, 화면 전체만 새 묶음으로 바꿉니다. 화면이 하나 늘어도 업데이트 장치를 하나 더 만들지 않습니다.

게임을 유지하는 부분과 바꾸는 부분

여기서 실행부는 브라우저 안에서 계속 돌아가는 코드입니다. 서버의 게임 로직 worker와는 다릅니다. Colyseus는 실시간 접속 서버, PocketBase(PB)는 계정과 지갑·원장을 저장하는 별도 서버입니다. 이번 화면 OTA는 worker나 PB를 재시작하지 않습니다.

상점 화면을 만들 수 있다는 것과 실제 구매 기능이 생기는 것은 다릅니다. 구매에는 서버의 잔액 검사와 원장 저장이 필요합니다. 이번 작업은 현재 미니멀 게임을 유지하며, 보류한 상점·채팅·미니룸을 새로 구현하지 않습니다.

15초마다 묻는 대신, 배포할 때 알립니다

  1. 새 파일 게시: 배포 도구가 Cloudflare에 전체 UI를 올리고 공개 파일·해시를 확인합니다.
  2. 현재 버전 등록: 비공개 관리 경로로 게임 접속 서버에 버전을 등록합니다. 서버는 디스크에 기록한 뒤 기존 연결로 알립니다.
  3. 뒤에서 준비: 브라우저가 새 파일을 받는 동안 이전 화면과 게임은 그대로 돌아갑니다.
  4. 안전할 때 교체: 새 화면과 첫 그리기가 확인되면 전환합니다. 한글 입력 조합·터치 이동 중에는 입력을 취소하지 않고 기다립니다.

입장·재접속·탭 복귀 때 현재 버전을 다시 확인하므로 연결이 끊겨 놓친 알림을 보완합니다. 미입장 탭에는 게임 연결이 없어 최초 로드·탭 복귀·입장 전의 단발 확인을 사용합니다. 주기 폴링이나 별도 알림 연결을 추가하지 않습니다.

Git 자동 빌드도 버전 등록 단계에 연결해야 합니다. 파일 게시만 되고 등록에 실패하면 “게시 성공·활성화 실패”로 남기고 등록만 다시 시도합니다. 알림을 완전히 누락한 게시가 계속 열린 탭에 즉시 반영된다고 약속하지 않습니다.

잘못된 업데이트는 화면만 되돌립니다

다운로드나 준비가 실패하면 기존 UI로 계속 플레이합니다. 새 UI 실행 중 문제가 나면 직전 UI로 돌아갑니다. 그 사이 움직인 위치, 획득한 별, 완료된 저장을 과거 상태로 되감지 않습니다. 업데이트 실패와 실제 연결 장애는 따로 표시합니다.

처음 이 구조를 받는 탭은 한 번 새로 입장해야 합니다. 이후 호환되는 화면과 리소스는 새로고침 없이 반영합니다. 실행부 자체의 비호환 변경까지 무조건 교체하는 구조는 아닙니다.
