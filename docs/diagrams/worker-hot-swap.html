01 · 접속은 유지하고 worker만 교체

주황색 접속·상태 관리는 그대로 둡니다. 실행 중인 worker가 게임을 처리하는 동안 새 worker는 상태를 복사하고 이후 입력을 처리합니다. 별 정산은 공통 저장 대기함과 DB를 거칩니다.

이어받을 상태

새 worker는 플레이어 위치와 모은 별, 진행 중인 판, 맵의 별 목록과 다음 생성 시간, 이동 제한, 저장 중인 정산을 이어받습니다.

worker-host.js가 체크포인트와 대기 입력을 메모리에 보관합니다.

화면과 입력

같은 방에서 위치·점수를 유지한 채 계속 걷습니다. 내 움직임은 즉시 화면에 반영하고 다른 사람의 움직임은 기존처럼 보간해 표시합니다.

정상 교체 중에는 재접속 안내를 띄우거나 입력을 막지 않습니다.

02 · 상태를 맞춘 뒤 worker 전환

실행 중인 worker는 새 worker를 준비하는 동안에도 입력을 처리합니다. 새 worker는 현재 상태를 복사하고 복사 중에 들어온 입력도 순서대로 처리합니다. 두 결과가 같아야 교체합니다.

교체 중 별이 3개에서 4개로 늘어난 경우
처음 복사한 상태가 3개여도 이후 획득 기록을 처리하면 4개가 됩니다. 새 worker도 4개인 것을 확인한 뒤 교체합니다. 아직 3개라면 교체하지 않습니다.
코드의 전환 조건

ready && replayed ≥ 1 && candidate.sequence === state.sequence
&& !candidate.pending && !inFlight && lastWasTick

내부 sequence는 입퇴장·이동·틱을 포함한 이벤트 배치 순서입니다. 브라우저의 이동 seq와 구분합니다.

03 · 정산과 장애 복구

파일 기록 후 정산 알림과 DB 저장

지급할 별의 수를 저장 대기함에 파일로 기록한 뒤 정산을 알리고 DB로 보냅니다.

DB 전송이 늦거나 실패해도 파일을 남겨 다시 보냅니다. 화면에서 DB 저장까지 확인한 별만 “저장된 별”로 표시합니다.

match ID와 전체 내용을 비교하고 원장에 unique 제약을 적용해 재전송 때 중복 지급을 막습니다.

교체 실패와 실행 장애

새 worker가 시작하지 못하거나 결과가 다르거나 준비가 3초를 넘으면 교체를 취소합니다. 실행 중인 worker는 계속 처리합니다. 실행 중인 worker가 멈춘 경우에는 마지막 확정 상태와 미완료 입력으로 복구를 시도합니다.

복구에도 실패하면 서버를 실패 상태로 표시하고 기존 장애 안내를 적용합니다.

복구는 메모리 상태 재생입니다. 자동 코드 롤백이나 호스트 장애 복구는 구현 범위가 아닙니다.

접속 서버 재시작은 별도 작업입니다.
이 구조에서 교체하는 대상은 게임 worker입니다. 접속 서버·DB 재시작이나 컴퓨터 재부팅은 무중단 범위에 포함하지 않습니다.
