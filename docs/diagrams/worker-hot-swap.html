게임 로직 무중단 배포

worker는 Colyseus 서버 안에서 이동·충돌·별 획득·점수를 계산합니다. Colyseus 전체나 PocketBase(PB)를 묶어서 부르는 말이 아닙니다. 접속을 담당하는 부분과 PB는 계속 실행하고 게임 계산을 맡은 worker만 새 버전으로 교체합니다.

00 · Colyseus, worker, PB는 각각 무엇인가요?

Colyseus는 플레이어의 실시간 접속을 관리하는 게임 서버입니다. 플레이어가 어느 방에 들어와 있는지 관리하고 이동 입력을 받아 현재 게임 상태를 화면으로 보냅니다.

게임 worker는 그 Colyseus 서버 안에서 게임 계산만 맡습니다. “이 위치로 걸어갈 수 있는가”, “누가 별을 주웠는가”, “이번 판 점수는 얼마인가”를 계산합니다. Node.js의 별도 실행 스레드로, 같은 서버 프로그램 안에서 실행합니다. 새 컴퓨터나 별도 Colyseus 서버가 아닙니다.

PB는 PocketBase의 줄임말이며 별도로 실행하는 계정·저장 서버입니다. 계정과 프로필, 저장이 끝난 별과 정산 내역을 보관합니다. 플레이 중인 위치와 아직 정산하지 않은 점수는 매 순간 DB에 쓰지 않습니다.

게임 로직 배포 때 바뀌는 부분과 유지하는 부분
구성담당하는 일worker 배포 때
Colyseus의 접속·상태 관리유저 연결, 방, 입력 순서와 마지막 확정 위치·점수 보관계속 실행
게임 worker이동·충돌·별 획득·점수 계산새 버전으로 교체
저장 대기함(outbox)DB에 보낼 정산 내용을 파일로 남기고 재전송계속 사용
PocketBase(PB)계정·프로필·저장된 별·정산 원장 관리계속 실행

방향키를 누르면 어떻게 처리되나요?

  1. 화면이 이동 입력을 Colyseus로 보냅니다.
  2. Colyseus가 입력을 게임 worker에 전달합니다.
  3. worker가 이동 가능 여부와 별 획득을 계산해 결과를 돌려줍니다.
  4. Colyseus가 결과를 확정·보관하고 플레이어들에게 현재 상태를 보냅니다.
  5. 판이 정산되면 정산 내용을 저장 대기함에 기록하고 PB에 저장합니다.

배포 때는 3번을 맡는 worker를 바꿉니다. 새 게임 worker가 현재 위치·점수와 그동안 추가된 입력을 따라 처리하는 동안 기존 worker는 계속 게임을 진행합니다. 둘의 최신 결과가 같은 것을 확인한 뒤 다음 입력부터 새 게임 worker에 맡깁니다. 연결은 계속 같은 Colyseus가 관리하므로 재접속하지 않습니다.

이 문서에서 말하는 무중단의 범위

현재 게임 상태와 입력 규칙을 유지하는 worker 코드를 교체합니다. 서버의 다른 파일은 이 절차로 교체하지 않습니다.

바꾸는 대상현재 방식으로 처리할 수 있나요?
같은 상태·입력 계약을 지키는 게임 worker 코드가능. 새 코드가 현재 게임 결과를 그대로 이어받는지 확인한 뒤 교체합니다.
맵·이동 속도·입력 형식·게임 상태 형식버전을 나누고 기존 상태를 새 규칙으로 옮기는 절차가 필요합니다. 기존 화면과 새 게임 worker의 규칙이 다르면 정상 입력도 거절될 수 있습니다.
Colyseus 접속 서버 자체 코드현재는 이 서버를 재시작해 반영하므로 연결이 끊깁니다. worker 교체와 별도입니다.
PB 실행 파일·DB 구조·저장 처리별도 배포·검증 대상입니다. worker 교체 검증이 PB 업데이트의 무중단을 보장하지 않습니다.
게임 화면(프런트)Pages에 별도로 게시합니다. worker 교체만으로 이미 열린 탭의 화면 코드가 바뀌지는 않습니다.
Mac mini 재부팅접속 서버도 멈추므로 연결이 끊깁니다. 이번 구현의 범위 밖입니다.

Colyseus 수정·게임 로직 수정·PB 수정은 어떻게 반영하나요?

게임 로직 수정: 같은 상태·입력 계약을 지키는 worker 코드를 새 release에 준비하고 교체를 요청합니다. 현재 worker가 계속 처리하는 동안 새 worker의 결과를 확인한 뒤 전환합니다. 85명·3분 주기 관찰 배포는 이 경로를 사용했고 사용자 요청으로 중지했습니다.

Colyseus 접속 서버 수정: 방 관리·인증·메시지 전달·WorkerHost 같은 접속 서버 코드를 바꾸는 경우입니다. 파일을 복사해도 실행 중인 프로그램이 자동으로 새 코드를 읽지는 않습니다. 현재는 프로그램을 재시작해야 하며 이때 게임 연결도 끊깁니다. 저장된 별은 DB에 남습니다. 진행 중인 위치·점수를 유지하려면 별도 작업이 필요합니다.

PB 수정: 무엇을 바꾸는지에 따라 다릅니다. 일반 데이터 변경, PB 서버 코드 변경, DB 구조 변경을 구분합니다.

PB에서 바꾸는 것현재 반영 방식
허용된 일반 데이터PB API로 저장하면 DB에 반영됩니다. 화면에서는 다음 조회나 갱신 때 확인합니다. 서버 코드 배포와는 다릅니다.
게스트 발급·지갑 조회·정산 처리 코드pb_hooks 파일 변경 후 PB를 재시작해야 합니다. 현재 --hooksWatch=false로 실행하므로 파일만 덮어써서는 반영되지 않습니다.
컬렉션·필드·관계·인덱스 등 DB 구조백업과 명시적인 데이터 이행이 필요합니다. 현재 --automigrate=false이며 호환되지 않는 기존 스키마는 시작 시 거절합니다. 코드를 복사하거나 재시작한다고 기존 데이터를 자동 변환하지 않습니다.
PB 실행 파일 버전별도 업데이트와 재시작·백업 복구 검증이 필요합니다. 실행 파일을 교체해도 현재 실행 중인 버전이 바로 바뀌지 않습니다.

PB와 Colyseus를 각각 실행하고 종료하도록 나눴습니다. 기존에는 com.fastmake.pixeltown.minimal이 PB와 Colyseus를 함께 관리해 PB 종료가 게임 종료로 이어졌습니다. 2026-10-08에 PB 전용 com.fastmake.pixeltown.minimal.pocketbase와 게임 전용 com.fastmake.pixeltown.minimal.colyseus로 운영 서비스를 분리했습니다. 이후 PB 배포 때는 PB 서비스만 재시작합니다. SDK 1개와 실제 브라우저 1개가 이동하는 동안 PB hooks 교체와 원본 복구를 확인했습니다.

PB가 꺼져도 기존 접속자는 같은 방에서 이동하고 별을 모읍니다. 정산은 디스크 저장 대기함에 남았다가 PB 복구 후 저장합니다. 지갑은 마지막 확인값을 미확인으로 표시합니다. 새 게스트 발급과 새 입장은 실패할 수 있으며 PB 복구 뒤 다시 시도합니다. PB 단독 배포 절차. DB 구조 변경과 실행 파일 업그레이드의 호환성 검증은 별도입니다.

사용자가 여는 게임 주소와 백엔드 주소도 일반 worker 교체 때는 그대로입니다. 새 미니멀 서버를 처음 도입하면서 백엔드 주소를 분리한 작업과, 그 서버 안에서 worker만 교체하는 작업은 다릅니다.

01 · 접속은 유지하고 worker만 교체

점선 테두리 안은 하나의 Colyseus 서버 프로그램입니다. 접속·상태 관리, 현재 worker, 새 게임 worker와 저장 대기함이 그 안에 있습니다. PB는 테두리 밖에서 별도로 실행합니다. worker 배포 때 주황색 접속·상태 관리와 PB는 그대로 둡니다.

이어받을 상태

새 게임 worker는 플레이어 위치와 모은 별, 진행 중인 판, 맵의 별 목록과 다음 생성 시간, 이동 제한, 저장 중인 정산을 이어받습니다.

worker-host.js가 체크포인트와 대기 입력을 메모리에 보관합니다.

화면과 입력

같은 방에서 위치·점수를 유지한 채 계속 걷습니다. 내 움직임은 즉시 화면에 반영하고 다른 사람의 움직임은 서버가 확인한 걸음을 순서대로 재생합니다.

정상 교체 중에는 재접속 안내를 띄우거나 입력을 막지 않습니다.

02 · 상태를 맞춘 뒤 worker 전환

현재 게임 worker는 새 게임 worker를 준비하는 동안에도 입력을 처리합니다. 새 게임 worker는 현재 상태를 복사하고 복사 중에 들어온 입력도 순서대로 처리합니다. 두 결과가 같아야 교체합니다.

교체 중 별이 3개에서 4개로 늘어난 경우
처음 복사한 상태가 3개여도 이후 획득 기록을 처리하면 4개가 됩니다. 새 게임 worker도 4개인 것을 확인한 뒤 교체합니다. 아직 3개라면 교체하지 않습니다.
코드의 전환 조건

ready && replayed ≥ 1 && candidate.sequence === state.sequence
&& !candidate.pending && !inFlight && lastWasTick

내부 sequence는 입퇴장·이동·틱을 포함한 이벤트 배치 순서입니다. 브라우저의 이동 seq와 구분합니다.

03 · 정산과 장애 복구

파일 기록 후 정산 알림과 DB 저장

지급할 별의 수를 저장 대기함에 파일로 기록한 뒤 정산을 알리고 DB로 보냅니다.

DB 전송이 늦거나 실패해도 파일을 남겨 다시 보냅니다. DB 저장을 확인한 별만 화면에 “저장된 별”로 표시합니다.

match ID와 정산 내용 전체를 비교합니다. 원장의 unique 제약으로 재전송해도 중복 지급하지 않습니다.

교체 실패와 실행 장애

새 게임 worker가 시작하지 못하거나 결과가 다르거나 준비가 3초를 넘으면 교체를 취소합니다. 현재 게임 worker는 계속 처리합니다. 현재 게임 worker가 멈춘 경우에는 마지막 확정 상태와 미완료 입력으로 복구를 시도합니다.

복구에도 실패하면 서버를 실패 상태로 표시하고 기존 장애 안내를 적용합니다.

메모리에 남은 상태를 다시 처리해 복구합니다. 코드를 자동으로 이전 버전으로 돌리거나 호스트 장애를 복구하지는 않습니다.

접속 서버 재시작은 별도 작업입니다.
이 구조에서 교체하는 대상은 게임 worker입니다. 접속 서버 재시작과 컴퓨터 재부팅은 연결을 끊습니다. PB만 재시작할 때는 기존 게임 연결을 유지하며 새 입장과 지갑 조회는 잠시 실패할 수 있습니다.
