01

도입 전: 접속과 게임 실행이 같은 스레드

로컬의 단일 메인 로비에서 이동·별 획득·정산을 실행합니다. Colyseus를 재시작하면 접속도 끊깁니다. Simulation을 파일로 분리한 것만으로 무중단 교체가 되지는 않습니다.

새 기본 실행은 최소환경

npm run dev:all로 세 서비스를 실행합니다. 개발 데이터는 .local/minimal 아래에 분리합니다.

웹
minimal/game · 5270
게임 서버
colyseus/minimal · 12620
DB / 훅
pocketbase/minimal · 18120

기존 게임과 DB는 그대로 보존

기존 환경은 npm run dev:legacy로 명시적으로 실행합니다. 새 최소환경이 기존 DB를 대체하거나 덮어쓰지 않습니다.

game/src
colyseus/*.js
pocketbase/pb_hooks

Cloudflare Pages는 정적 웹과 안내 페이지의 운영 제공 위치입니다. 이번 최소환경은 아직 배포하지 않았습니다.

02

현재 로컬 구현: 연결 유지·게임 worker 교체

별도 로컬 환경에서 구현·검증했습니다. Colyseus 접속계층은 연결·룸·세션을 계속 보유합니다. 새 worker가 현재 상태를 따라잡은 뒤, 한 틱의 경계에서 실행 권한을 넘깁니다.

  1. 준비하고 따라잡기

    현재 worker가 게임을 계속 진행합니다. 준비 worker는 상태를 넘겨받고 입력을 같은 순서로 재생해 틱을 따라잡습니다. 준비·검증 실패 시 교체하지 않습니다.

  2. 틱 경계에서 전환

    합의한 틱까지 기존 실행이 책임지고, 다음 틱부터 새 worker에 권한을 넘깁니다. 접속계층의 입력 순서와 연결·룸·세션은 유지합니다.

  3. 늦은 결과 차단

    응답 전송과 정산 모두 현재 권한 세대만 허용합니다. 구 worker가 뒤늦게 보낸 결과는 거절하고, 정산은 단일 outbox 경로로만 처리합니다.

  4. 확인 후 기존 종료

    전환 확인 뒤 구 worker를 종료합니다. 구 worker를 무기한 남기거나 사용자에게 재접속을 시켜 배포를 끝내는 방식이 아닙니다.

03

실제 장애는 사용자에게 알려야 합니다

이번 목표가 다루는 범위

검증한 무중단 대상은 게임 worker 코드 교체입니다. 후보 추격·상태 비교·권한 전환을 실제 100명 로컬 활동과 두 브라우저에서 확인했습니다.

PocketBase 재시작·호스트 재부팅·접속계층 자체의 중단까지 무중단으로 만드는 작업은 포함하지 않습니다. worker 장애는 최신 확정 상태와 처리 중 이벤트를 재생하며 단위 실패 주입으로 검증했습니다. 접속 프로세스 손실까지 복구하지는 않습니다.

연결 실패를 정상 플레이처럼 보이지 않게

게임 서버에 연결할 수 없으면 입력을 막고 상태를 안내해야 합니다. 정적 웹과 unavailable.html은 Cloudflare Pages에서 독립 제공할 대상으로, 현재는 로컬 Vite에서 확인합니다.

안내 예시 · 실제 서비스 상태 표시가 아닙니다

“광장에 잠시 연결할 수 없어요. 잠시 후 다시 입장해 주세요.”

저장된 별과 정산 대기 별을 구분하고, 저장 확인 전에는 완료로 안내하지 않습니다. 장애 때의 재접속 안내는 배포 중 worker 교체 방식과 구분합니다.

구성: 정적 HTML + inline SVG 2개 · JavaScript 없음 · 외부 리소스 요청 없음 · 기본 밝은 프로필 · 4px 기준 배치

글꼴은 설치된 Geist / Instrument Serif / Noto 계열을 우선 사용합니다. 오프라인에서는 Apple SD Gothic Neo·맑은 고딕 및 로컬 명조·시스템 글꼴로 대체됩니다.

표현 범위: 도입 전 도식 5개 노드 / 현재 도식 6개 노드. 구현 경로·포트는 본문에 표기했으며, 인증·개인 원장 조회와 상세 장애 복구 절차는 도식에서 생략했습니다.
