# PixelTown 게임기획서 · 제품 요구사항 정본

작성 기준: 2026-10-02. 자체 도트 타운의 승인 요구사항을 정리한다. 이미 프런트엔드·백엔드·검증 구현이 병렬 진행 중이며 현재 진척과 실행 증거는 [PROJECT_STATUS](03_PROJECT_STATUS.md)에서 관리한다.

<a id="game-design"></a>
## 1. 게임 정의와 콘셉트

PixelTown은 작은 2D 도트 마을에서 이웃과 산책하고 채팅하며 짧은 별 모으기를 즐기는 localhost 멀티플레이 데모다. 원 서비스의 통신망·자산을 재사용하지 않고 직접 그린 지형과 캐릭터로 구성한다. 화면의 주인공은 실제 플레이 가능한 타운이며 수치 카드나 관리 대시보드가 아니다.

타운 광장(`lobby`)은 만남과 첫 이동, 비밀 정원(`garden`)은 산책과 대화, 스타 아케이드(`arcade`)는 별 모으기 참여를 유도하는 공간이다. 현재 게임 시작 계약은 세 장소 모두에 적용된다. 아케이드 전용 제한을 임의로 추가하지 않는다.

## 2. 목표와 범위

목표는 로그인 → 마을 입장 → 이동·충돌·채팅 → 게임 → 점수·보상 조회를 실제 로컬 서버로 연결하는 것이다. 서로 다른 두 계정으로 타인의 접속·이동·채팅을 확인하고 짧은 20명 로컬 smoke로 기능이 멈추지 않는지 검사한다. 100명은 이후 측정·확장 목표이며 현재 수용력 보증이 아니다.

이번 범위에는 자체 도트 Canvas, 카메라 추적, 키보드·모바일 이동, 3개 장소, 서버 권한 게임, 사용자별 기록, 저장 장애 복구가 포함된다. 상점·결제·친구 DM·개인 공원 꾸미기·100명 인터넷 운영·운영 관리자 UI는 후속 범위다. 회원가입은 최종 범위에서 제외하며 개발 계정과 기존 계정 로그인만 제공한다. 공개 GitHub 저장소는 소스 전달이며 운영 서비스 공개 배포를 의미하지 않는다.

## 3. 플레이어와 동기

| 플레이어 | 목적 | 대표 행동 |
|---|---|---|
| 첫 방문자 | 조작을 배우고 이웃을 만남 | 개발 계정 로그인, 광장 이동, 인사 |
| 친구와 접속한 사용자 | 같은 장소에서 가볍게 교류 | 장소 선택, presence 확인, 방 채팅 |
| 짧은 게임 참여자 | 제한 시간 동안 더 많은 별 확보 | 게임 시작, 별 근처 이동, 순위·보상 확인 |
| 모바일 방문자 | 작은 화면에서도 조작·대화 | 터치 방향패드, 채팅 접기, 내부 스크롤 |

공개 개발 시드 `demo1@pixeltown.local`, `demo2@pixeltown.local`과 비밀번호 `PixelTown123!`는 localhost 데모 전용이다. 실제 계정·운영 인증정보를 공개 문서에 넣지 않는다.

## 4. 핵심 루프와 게임 경험

`로그인 → 장소 입장 → 이동·대화 → 별 모으기 시작 → 별 가까이 이동 → 서버 점수 갱신 → 종료 순위 확인 → 기록·별 보상 조회 → 다시 산책/도전`.

### 플레이 규칙

- 한 방에서 한 라운드를 공유한다. 기본 제한 시간은 30초이며 시작 시 별 5개를 배치한다. 방별 미회수 별 상한은 12개다. 시작 시 접속자와 진행 중 합류자에게 점수 0으로 참여 기회를 준다.
- WASD/방향키 또는 터치 방향패드로 걷는다. 장애물과 맵 경계를 통과할 수 없다. 별 가까이 걸으면 수집 요청이 발생한다.
- 서버가 별까지의 거리가 32 월드 단위 이하인지 확인한다. 성공한 별 한 개는 1점이며 같은 별은 먼저 승인된 사용자만 얻는다.
- 진행 중 1500ms마다 미회수 별이 12개 미만이면 1개를 생성한다. 이미 상한 이상이면 생성하지 않는다. 회수 후 빈 공간은 이후 주기에 1개씩 채우며 여러 주기의 누락분을 한 번에 누적 생성하지 않는다.
- 제한 시간이 지나면 종료한다. 별이 0개가 되어도 즉시 종료하지 않고 다음 생성 주기를 기다린다. 각 참가자 점수를 비교하는 작은 상위 3명 scoreboard와 남은 별/상한을 보여준다. 가장 많은 별을 모으는 것이 목표이며 승자 전용 추가 보상은 없다. 동점은 같은 순위(예: 1, 1, 3)로 표시한다.
- 개인 별 보상 수량은 최종 점수와 같다. 0점도 참가 결과와 수량 0 원장을 남긴다. 라운드마다 결과·보상은 사용자당 한 번만 확정한다.
- 진행 중 떠난 사용자의 기존 점수는 종료 원장에 남는다. 방에 아무도 남지 않으면 해당 라운드를 종료 처리한다. 나중 재입장한 동일 사용자가 같은 라운드에서 중복 점수를 만들 수 없다.

### 실패 경험

로그인 실패는 인증 화면에 이유를 표시하고 재입력을 허용한다. 연결이 끊기면 연결 상태·재연결 액션을 보여주고 멀티플레이 입력을 비활성화한다. 방 이동 시 기존 채팅과 위치 상태를 새 방 것으로 바꾼다. 같은 사용자의 같은 방 중복 접속은 안내하고 거절한다.

DB 저장이 지연되면 게임 결과를 없애거나 보상을 즉시 확정한 것처럼 보이지 않는다. “기록 저장 중/재시도 중”을 표시하고 저장 완료 후 수첩을 갱신한다. 조회 실패와 실제 빈 인벤토리는 구분한다. 혼자 둘러보기는 로컬 연습으로 명확히 표시하며 서버 기록·보상으로 인정하지 않는다.

| FR-007 게임 중심 레이아웃 | 자체 도트 지형·캐릭터, 전체 화면 Canvas, 게임 내 HUD·수첩·채팅 | 데스크톱/모바일 가로 넘침·페이지 스크롤 방지; 패널만 내부 스크롤 | AC-011 |
| FR-008 로컬 실행·검증 | React/Vite·PB·Colyseus를 localhost에서 실행, 20명 짧은 smoke | 사용 중 포트를 임의 종료하지 않음; 외부 원 서비스에 연결하지 않음 | AC-012 |

FR-001은 개발 계정·기존 계정 로그인만 제공한다. 회원가입 UI·공개 회원가입 endpoint는 만들지 않는다. 방에 입장할 기존 계정은 사전에 사용자 프로필을 갖추어야 한다.

FR-004 상세: 배경 alpha 범위는 20–95%다. 패널 전체 `opacity`를 적용하지 않고 글자·아이콘·입력·버튼은 불투명하게 유지한다. 슬라이더에는 값·라벨을 제공하며 키보드로 조절할 수 있다. 투명도 설정은 localStorage에 저장하고 새로고침 후 복원한다. 접힌 동안 수신한 다른 사용자 메시지는 미읽음 배지에 누적하고 펼칠 때 해제한다. 전체 과거 메시지 개수를 미읽음으로 표시하지 않는다. 설정에는 토큰·채팅 원문을 복제하지 않는다.

## 6. 화면과 UI 상태

| 화면 ID | 주요 구성·액션 | 상태와 반응 |
|---|---|---|
| SCREEN-001 인증 | 도트 배경, 이메일·비밀번호, 개발 계정 입력, 혼자 둘러보기 | 대기/인증 중/실패/성공; 중복 제출 방지; 오류 `role=alert` |
| SCREEN-002 타운 | Canvas, 추적 캐릭터, 장소 선택, 접속 상태·인원, 인사, 키 안내·터치패드 | 연결 중/온라인/끊김/연습; 재연결; 장소 이동 시 입력 정리 |
| SCREEN-003 게임 HUD | 시작, 남은 초, 개인 별 점수, 상위 3명 scoreboard·동점 순위·남은 별/상한·종료 점수 | 대기/진행/종료/저장 중/재시도/저장 완료; 진행 중 시작 비활성 |
| SCREEN-004 채팅 overlay | 게임 위 고정 패널, 로그 내부 스크롤, 입력·전송, 접기·펼치기, 20–95% 배경 슬라이더 | 빈 상태/수신/접힘+미읽음/연결 불가; 본문과 조작부 불투명; 새로고침 시 투명도 설정 복원 |
| SCREEN-005 내 수첩 | 사용자 프로필, 인벤토리, 최근 결과, 새로고침·닫기·로그아웃 | 로딩/빈 결과/성공/조회 오류; 내용만 내부 스크롤; 자신의 원장만 표시 |

데스크톱은 상단 장소·presence, 화면 내부 장소 설명·게임 HUD, 하단 대화·인사 조작을 둔다. 모바일은 게임 시야, 방향패드, 채팅 입력이 서로 가리지 않도록 배치하고 작은 화면에서는 설명·보조 안내를 줄인다. 가상 키보드가 열려도 입력과 전송 버튼을 볼 수 있어야 한다. 문서 페이지가 세로·가로로 밀리지 않아야 하며 게임·채팅·수첩이 별도의 대시보드 페이지로 분리되지 않는다.

버튼·입력·슬라이더는 키보드 포커스로 조작 가능해야 한다. 채팅 입력 시 WASD를 이동으로 처리하지 않고 blur/visibilitychange에서 이동을 중지한다. 접기 버튼에 `aria-expanded`, 입력·터치 방향·슬라이더에 읽을 수 있는 라벨을 제공한다. Canvas는 시각적 플레이 영역이며 전체 게임을 스크린리더만으로 플레이 가능하다는 보장은 이번 범위에 없다.

| BR-003 | 이동·경계·장애물 충돌·별 거리·시간·점수는 서버 권한이다. 대각선 이동으로 빨라지지 않는다. |

| BR-008 | 채팅 배경만 20–95% alpha; 텍스트·조작부 불투명; 설정 로컬 복원; 접힌 동안의 미읽음만 배지로 표시한다. |
| BR-009 | 연습 모드는 멀티플레이와 영구 보상이 없는 로컬 경험이다. 서버 검증·20명 검증의 증거로 사용하지 않는다. |

| BR-010 | 20명은 로컬 짧은 기능 smoke, 100명은 미래 목표다. 미실행 성능·인터넷 접속을 통과로 표현하지 않는다. |
