# 별 소비·사용자 상태 변경 조사

- 조사일: 2026-10-08. 코드 기준: `45fcdd5`.
- 목적: 게임을 최소 기능으로 제한하기 전에 변경 가능한 상태와 외부 부수 효과를 확인한다.
- 범위: 저장소의 프런트, Colyseus, PocketBase 게임 hooks, 카탈로그, seed·계정 관리 경로. 운영 서버를 다시 조사하거나 변경한 결과가 아니다.
- 현재 동작을 기록한다. 최소 모드와 무중단 배포는 아직 구현하지 않았다. 실행 순서는 [PLAN-007](../plans/PLAN-007.md), 실행 검증 결과는 [PROJECT_STATUS](../03_PROJECT_STATUS.md)에 둔다.

## 1. 별을 소비하는 행위 전체

일반 사용자에게 실제 별 차감을 일으키는 서버 경로는 **`POST /api/pixeltown/shop/buy` 하나**다. [shop.pb.js](../../pocketbase/pb_hooks/shop.pb.js)는 카탈로그 가격으로 `purchases` 행을 만들고 같은 트랜잭션 안에서 잔액이 음수면 롤백한다. 별 잔액 필드를 직접 감소시키지 않는다.

[catalog.json](../../shared/catalog.json) 기준 총 24종, 전부 한 번씩 구매하면 298별. `(user,item)` unique로 동일 상품은 한 번만 소유한다. 반복 소비형 아이템·사용료·강화·선물·거래·판매·환불 경로는 현재 게임 코드에 없다. 카탈로그 가격 변경은 기존 `purchases.price`를 다시 계산하지 않는다.

다음 동작은 **별을 소비하지 않는다**: 모자·옷·펫 장착/해제, 닉네임·피부·머리색·머리 모양·기본 옷 색 변경, 가구 놓기·옮기기·치우기·배치 저장, 장소 이동, 미니룸 출입, 채팅·인사. 펫에는 별 소비·획득을 자동 수행하는 AI가 없다.

## 4. 실시간 방·연결에서 바뀌는 상태

| 행위 | 상태 변화 | 무중단 인계 시 보존할 것 |
|---|---|---|
| 방 입장 | 세션 생성, 입구 위치·외형 등록, 현재 기간 점수 항목 추가 | 사용자↔세션↔룸 매핑, 정원 예약·진입 중 요청 |
| 키보드·방향패드·클릭 이동 | 위치, 이동 허용 거리, 입력 `seq`/응답 `ack`, 보정 `fix` | 위치만 복사하면 부족. 미처리 입력·이동 예산·시간·보정 번호까지 필요 |
| 충돌·잘못된 이동 보고 | 이동 거부와 `fix` 증가 | 전환 때문에 정상 입력이 오인 거부되지 않아야 함 |

| 인사 | 서버 broadcast, 개인 cooldown·표시 기한 | 영속 보상 없음. 펫 움직임·걷기 애니메이션도 표시 상태 |
| 외형 다시 읽기 (`look`) | PB 비동기 조회 후 룸 플레이어 이름·외형 갱신 | 진행 중 비동기 작업의 뒤늦은 결과가 새 상태를 덮지 않도록 버전 관리 |
| 연결 끊김 | 이동 예산 제거, 재접속 예약·끊김 집계 | 15초 예약, 세션/소켓은 접속 계층 소유. Promise 자체를 복사하지 않음 |
| 같은 세션 재접속 | 기존 플레이어 유지, 예약 해제 | 재접속은 장애 복구용이며 정상 배포 절차로 사용하지 않음 |
| 새로고침·새 세션 | 끊긴 동일 사용자 세션 대체, 위치는 입구에서 새로 시작 | 활성 중복 접속은 같은 룸에서 거절. 룸 간 사용자 단일 접속 보장은 별도 |
| 퇴장·탭 종료·재접속 만료 | 플레이어·이동 예산·cooldown 제거 | 양수 점수 보존, 마지막 사람은 즉시 정산 |
| 서버 종료·룸 dispose | 진행 중 정산 시도, 연결 종료 | 현행 종료 동작은 그대로 새 worker 폐기 절차에 재사용하면 안 됨 |

`Town`의 `players`, `moves`, `cooldowns`, `held`, `dropped`, `lookJobs`, `game`, `matchId`, `starCounter`, `nextStarAt`가 관련 상태다. `snapshot`은 그중 일부만 보내므로 네트워크 snapshot을 그대로 복사하는 것만으로 서버 상태 인계가 완성되지 않는다. 난수·UUID·서버 시각·PB 응답은 재실행 때 달라질 수 있어 이미 결정된 값 또는 재생 가능한 이벤트를 전달해야 한다.

## 5. 조사에서 확인한 시스템 우선 항목

1. **별 공급과 정원은 분리돼 있다.** 초기 5개·6초당 1개·맵 상한 12개. 첫 3분에 정상 생성 기회 29번을 모두 쓰면 최대 34개다. 100명이 들어왔다고 100명에게 지급되지 않는다. 64점은 룸 정원이 아니라 정산 합계 상한이다. 별을 늘릴 때 서버·DB 계약을 함께 검증해야 한다.
2. **없는 사용자 한 명 때문에 정산 전체가 실패할 수 있다.** `commit-match`는 모든 참가자를 한 트랜잭션에서 조회한다. 삭제된 사용자 처리 정책과 정산 전 계정 삭제 방지부터 정해야 한다.
3. **outbox 하나의 실패가 다른 정산을 막는다.** 파일 반복 전체에 단일 `try/catch`가 있다. 파일별 오류 격리·실패 내역 보존이 필요하다. 현재 `busy`는 한 프로세스 안에서만 유효하므로 두 worker가 같은 파일을 처리하게 하면 안 된다.
4. **전체 대기열 상태와 개인 정산 상태가 섞인다.** 전원에게 공용 `pending/saved`가 전송된다. 개인별 정산 완료 판정과 구분해야 한다.
5. **조회 실패·응답 역전이 지갑 표시를 바꿀 수 있다.** 원장 조회의 일부 실패를 빈 배열로 취급하거나 늦은 이전 응답을 적용하는 경로를 함께 수정해야 한다.
6. **무료 기능에도 경쟁 상태가 있다.** `equip`은 전체 슬롯을 대체한다. 이전 외형을 기준으로 동시에 만든 두 요청은 서로의 장착을 지울 수 있다. 가구 배치·프로필 역시 상태 버전 검사 없는 대체 저장이다.
7. **입장 제한도 상태다.** 가입 IP당 시간당 20요청과 연결당 초당 120메시지 제한은 서로 다른 계층이다. 신서버 전환 후 입력 재생을 사용자 도배로 계산하지 않도록 경계를 설계해야 한다. 100명 사전 발급 계정의 입장 통과만으로 신규 가입 100명 통과라고 할 수 없다.
8. **문서와 실제 코드 차이:** TECH_SPEC의 `look` 500ms cooldown 설명과 달리 코드는 진행 중 조회를 합칠 뿐 명시적 500ms 제한이 없다. `matches.pb.js`의 60초 생성량 주석은 기본 180초와 다르다. 무중단 구조 작업 때 계약/주석을 정리할 `DOC-CODE-MISMATCH`다.

이 항목들은 코드 검사와 이전 로컬 재현 기록에 근거한다. 기존 상세 증거는 Git 제외 자료 `.test-work/star-review-20261008/`에 있으며, 이번 조사에서 운영 장애나 UI 경쟁 상태를 다시 재현한 것은 아니다.

| 후속 재도입 | 채팅·인사 → 외형·장착 → 장소 이동 → 전체 상점·펫 → 미니룸 | 각 상태 변경이 배포 경계를 통과하는지 확인 후 확대 |

최소 모드는 구현 제안이며 아직 적용되지 않았다. 화면 버튼만 감추면 이전 탭·직접 API·타이머·포털을 통해 보류 기능이 실행된다. 화면·실시간 메시지·PB 변경 API에 같은 기능 허용 정책을 적용해야 한다. 보류 요청은 안내 가능한 거절 응답으로 끝내며 기존 WebSocket을 끊지 않는다.

기존 구매 원장·별·프로필·방 배치는 보존한다. 상점을 보류해도 잔액 계산에서 과거 구매를 빼는 규칙은 유지해야 한다. 기존 계정의 유료 외형은 저장값을 지우지 않고 최소 모드에서 기본 모습으로 표시할 수 있다. 자동 계정 정리와 관리자 작업은 테스트 사용자/진행 정산을 침범하지 않도록 별도 정책이 필요하다.

## 7. 접속 불가 안내 요구

PocketBase 자체 업데이트·Mac mini 재부팅의 무중단화는 범위 밖이다. 대신 현재 Cloudflare Pages에서 백엔드 없이도 열리는 안내 화면을 제공한다. Supabase·Vercel 이전은 전제하지 않는다.

- 첫 접속의 인증/게임 서버 연결 실패와 플레이 중 실제 통신 장애를 처리한다. 가입 429·닉네임 중복·인증 거절을 전부 서버 점검으로 표시하지 않는다.
- 상태 확인·자동 재시도·수동 재시도·마지막 확인 시각을 제공하고, 복구되지 않았는데 입장 가능으로 표시하지 않는다. 실제 장애 때 오프라인에서 별을 계속 확정 지급하지 않는다.
- 사용자 자격증명과 저장된 진행을 삭제하지 않는다. 정산 성공 여부를 확인하지 못한 경우 저장 완료라고 단정하지 않는다.
- 정상 게임 로직 배포 때는 이 안내가 나타나면 실패다. 연결 끊김을 숨겨 무중단으로 판정하지 않는다.
- 앱 JavaScript 초기화가 실패해도 열 수 있는 정적 안내 경로를 둔다. Cloudflare Pages 자체·사용자 인터넷 장애까지 이 페이지가 반드시 열린다고 보장하지 않는다.
