# 접속 복구·heartbeat 수정 검증

2026-10-09. 구현과 로컬 검증을 마쳤다. 운영에 배포하거나 공개 30분 검사를 다시 실행한 결과는 아니다. 이전 [종류별 30분 검사](2026-10-08-deployment-types-30min.md)의 실패 기록은 유지한다.

후속 운영 반영·정상입력 예측한도60걸음 수정·공개30분 결과는 [공개 재검사](2026-10-09-public-recovery-recheck.md)를 따른다. 아래 수치는 최초 로컬 검증 당시 기록이다.

## 무엇을 고쳤는가

연결이 끊긴 뒤 새 방에 들어가면 이전 위치와 입력을 이어받을 수 없었다. 이제 복구 토큰으로 같은 방·세션에 연결하고, 서버가 마지막으로 확인한 ack부터 남은 입력을 다시 보낸다. 게스트와 별 원장은 그대로 사용한다. 서버는 상태를 20초 보관하고, 클라이언트는 최대 12초·10회 복구를 시도한다. 끊긴 뒤 3초까지만 이동을 예측하며, 이후에는 위치를 고정하고 입력을 보존한다. 서버 보정이 필요했던 입력은 별도로 집계한다.

기존 heartbeat는 pong 응답 횟수만 보고 연결을 끝냈다. 새 heartbeat는 실제 ping 송신 완료부터 대기를 시작하고, 서버가 새로 승인한 이동도 생존 확인에 사용한다. 송신 큐에 ping이 6초 이상 머문 경우와 송신 후 pong·유효 이동이 6초 이상 없는 경우를 나눠 기록한다. 중복·거절된 이동으로 생존 시간을 늘릴 수는 없다.

메시지 허용량은 90개/초로 채우고 최대 240개를 모아 둔다. 지연된 정상 입력 묶음과 80개/초 복구 재전송을 받아들이며, 과다 송신은 4002로 종료한다. SDK가 정상 복구를 위해 기존 소켓을 정리하는 4002는 내부 과다 송신 표시와 구분했다. 이동 속도·충돌 검사를 완화하지 않았다.

화면 모듈은 첫 다운로드 실패 뒤 같은 URL로 다시 import하면 실패 캐시 때문에 즉시 재실패하는 현상을 브라우저에서 재현했다. 재시도 URL을 내부에서 바꾸고 최대 3회로 제한했다. 의존 모듈의 실패 캐시도 피하도록 실제 배포용 렌더러 JavaScript를 하나의 파일로 묶는다. 준비가 실패하면 기존 화면을 유지한다. 게시 도구는 파일 다운로드와 게시 전후 버전 확인에 제한 재시도를 사용하며 SHA와 게시 충돌 검사는 유지한다.

85명 검사의 입력 몰림은 정상60걸음과 과다250프레임을 나눴다. 정상60걸음은 ack를 확인했고, 별도 과다 송신 접속은 4002와 실제 종료 이유를 기록했다. 유효 이동을 하는 접속의 pong을 10초 막았을 때 끊김이 없었다. 그 뒤 이동과 pong을 모두 멈추자 서버가 종료했고 같은 위치·fix로 복귀했다. 이 의도적 종료는 자연 끊김으로 합산하지 않는다.

85명 검사는 짧은 왕복 이동과 별 수집1명을 사용했다. 이전 공개 검사처럼 전체 맵 무작위 이동80명·별 추적5명의 장시간 조건은 아니다. 실제 브라우저 별 점수는0이었으며 진행 점수 보존은 SDK의 실제 별 획득 뒤 TCP절단으로 확인했다. 100명 검사도 짧은 로컬 검사다.

화면 모듈 검사는 PB·게임 접속과 분리한 엔진에서 실제 Vite 빌드 파일을 사용했다. 첫 요청에503을 반환한 뒤 같은 manifest를 고유 query로 재시도해200과 실제 렌더링을 확인했다. 비보안 HTTP에서도 `randomUUID` 없이 시작했다. 기존 다중 JS 릴리스의 의존 파일 실패 캐시는 그대로 남으므로, 새 단일 JS 릴리스로 전환해야 이 수정이 적용된다. CSS·글꼴·이미지는 기존 manifest 파일 계약을 유지한다.

최종 단위·UI 재실행 로그와 소스 해시는 `.test-work/disconnect-fix-20261009/`에 보관했다. 빌드는 격리 복제본에서 수행해 기존 빌드 산출물을 덮어쓰지 않았다.

## 실패와 수정 기록

첫 85명 시도의 정상 입력 묶음 시험은 ack 시간 초과로 실패했다(`minimal-recovery-Meljhn`). 시험 좌표를 항상 x+4로 보내는 코드는 맵 경계나 장애물에 들어갈 수 있어 가능한 방향을 먼저 검사하도록 바꿨다. 다음 시도(`minimal-recovery-7Qa6Gr`)는 별이 하단에 반드시 있다는 시험 가정 때문에 실패했다. 현재 별 중 가장 가까운 것을 고르고 분수를 피하는 경로로 수정했다. 실패 보고서와 로그를 삭제하지 않았고, 통과 집계에 섞지 않았다.

통합 검토에서는 SDK가 정상 복구를 위해 기존 활성 소켓을 4002로 정리하는 경로를 발견했다. 과다 송신의 4002와 구분하지 않으면 정상 복구도 거절하게 되어 내부 표시로 구분하고 실제 서버 시험을 추가했다. UI의 모의 SDK 오류 코드도 설치 SDK에 맞춰522/524/525로 정정했다.

## 아직 확인되지 않은 것

- 공개 검사 heartbeat 종료244건의 최초 원인은 여전히 미확정이다. 이번 수정은 유효한 이동이 계속 오는 연결을 pong만 없다는 이유로 종료하지 않도록 하고, 실제 끊김 뒤 상태를 복구한다. 모든 공개 끊김을 없앴다는 결론은 아니다.
- Cloudflare가 재시작해 닫은 기존 소켓은 유지할 수 없다. 같은 게임 세션으로 연결을 다시 만드는 방식으로 대응한다. Cloudflare 실제 재시작을 이번 로컬 시험에서 발생시킨 것은 아니다.
- 이전 공개 검사 미확인 SDK725개·브라우저198개의 처리 여부는 소급해 확정하지 못했다. 이번 새 검사에서 pending0인 사실과 구분한다.
- 접속 프로세스나 호스트가 사라지면 같은 방의 메모리 상태도 없어진다. 이 경우는 실패 안내로 끝나며 디스크 위치 복원은 없다.
- 기존 탭에 접속 복구·updater 수정 자체를 화면 교체만으로 넣을 수 없다. 처음 한 번 새 프런트로 입장해야 한다. 이후 호환 렌더러·리소스 교체는 기존 방식대로 진행한다.

## 다음 작업과 보존 상태

운영 반영 후 배포 없는30분 기준 검사를 먼저 한다. 원시 소켓 끊김·같은 세션 복구 성공·복구 실패·보정 입력·미확인 입력을 따로 기록한다. 기준 검사가 통과하면 PB·worker·리소스·화면 코드의 종류별30분 검사를 진행한다. 짧은 성공이나 pending 초기화로 장시간 통과를 대신하지 않는다.

게임 접속 프로세스 수정은 worker 교체로 반영할 수 없으므로 최초 한 번 접속 호스트를 새 코드로 시작해야 한다. 운영 game은 앞선 검사 종료 뒤 중지된 상태를 유지했다. 이번 턴에는 운영 접속·배포·commit/push/merge를 하지 않았다. 로컬5270/18120/12620과 기존 미커밋 작업·개발 세션을 보존했다. 시험 소유 PB/game/proxy/Vite와 Ego space20만 정리했다. 시험 자료·DB·자격증명·원본 비교 자료는 정리 지시 전까지 보존한다.
